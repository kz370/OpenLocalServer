# OpenLocalServer v1.1.0 — CPU Caps, Localhost Routing, and a Real "Stop all"

**Version:** 1.1.0
**Release date:** 2026-09-29
**Platform:** Windows 10 / 11 (64-bit)
**License:** GPL-3.0-only
**Previous release:** [v1.0.0](./v1.0.0.md)

76 commits, 204 files changed (+13,626 / −4,587) since v1.0.0.

## ✨ Highlights

### CPU limits, on Windows

Settings → Resources can cap a service's CPU. `ols-core` wraps the process in
`cpulimit`, which is now vendored in `vendor/cpulimit/cpulimit.exe` and installed
next to the app, so nothing extra has to be installed. The limit is stated either
as a share of the whole CPU or as a thread count (the two are mutually
exclusive, and a thread count is converted against the machine's logical cores,
rounded up). A cap that is asked for but cannot be applied is a refusal naming
the fix — a service never silently runs uncapped under a card that says it is
limited. Applies to databases, caches, mail, custom services and all three web
servers.

### `localhost/<prefix>` now actually serves the site

A site with TLS and "Redirect to HTTPS" answered `http://localhost/shop/` with a
301 to `https://shop.test/` — the prefix route pointed at the site domain's own
redirect, so the route was unreachable. All three renderers (Nginx, Apache,
Caddy) now proxy to the site's HTTPS vhost with SNI, and send
`X-Forwarded-Prefix: /<prefix>` so an app rebuilding an absolute URL can put the
prefix back. Sites without TLS are unaffected.

The add-site form fills the localhost path from the project name too, next to the
folder and the domain, so one name fills all three places a site is identified —
and a slug too long to be valid writes nothing rather than an unsaveable prefix.

### One "Stop all"

There were two commands named Stop all, with different scopes, and neither was
right: the tray missed tunnels and supervised workers, the Dashboard button only
walked the auto-startup set from Settings → Startup — so Mailpit, started by hand,
survived it and the status mark stayed green. `CoreCommand::StopAll` is now the
single definition (tunnels → workers → web stack and PHP pools → services → a 10s
reap wait), used by the tray, the Dashboard and the HTTP `operate` allow-list, and
it names any process the OS refuses to kill instead of swallowing it.

## 🛠️ Other changes

- **Sites & web servers**: multiple web servers, each with its own HTTP/HTTPS
  ports, instead of a single pair; a configurable default TLD and project-name
  autofill in the domain dialog; site rows and the delete/apply path fixed
  (optimistic removal, no store mutex held across a multi-second apply, the
  project goes with its last site, and the confirm dialog names what it deletes).
- **Window & launch**: no transparent flash while the app boots — the pre-paint
  period paints the app background, and the window is revealed only once the UI
  has actually painted.
- **Layout**: Dashboard and Web server pages are fluid between `lg` and `xl`
  instead of crowding their controls; the Services card keeps its state, name and
  five colour-coded actions at every width.
- **Excluded sites**: a new card manages excluded sites and project folders.
- **Project imports**: SSH keys are detected, listed and selectable.
- **Icons**: app icons are built from master images by script; brand marks for
  pgAdmin, HeidiSQL, Memcached and Mailpit; theme-aware logo handling.
- **Logs**: per-service log sources, so a service can be opened on its own log
  rather than the shared one.
- **Robustness**: helper service replies time out instead of blocking forever;
  a poisoned core lock is recovered rather than panicking every later command;
  a site settings page can no longer hang on "Reading the project…" forever
  (gating reads have a deadline, an error state and a Retry); database backup no
  longer refuses a database whose name contains `-`, `.` or a space (only a name
  that cannot be a file name is refused).
- **State**: state storage is SQLite (`data/app.db`), with DB Browser integration.

## 🔒 Security

Unchanged from v1.0.0: every runtime download is SHA-256 verified, the local CA
key stays on-device, secrets live in the OS keyring only, tunnels require an
explicit first-exposure confirmation, and the vendored `cpulimit` hash is
self-pinned and recorded in `vendor/cpulimit/README.md` with its source and
retrieval date.

## ⚠️ Known limitations

Carried over from `docs/STATUS.md`; see the v1.0.0 notes for the full list.

- The installer, the helper UAC install and MariaDB import have still not been run
  end-to-end on a clean VM as a release gate.
- Tunnels locate provider binaries by hand rather than downloading them; streamed
  responses bypass the traffic inspector.
- Resource memory limits apply at the next service start.
- Windows only.

## 📋 Getting Started

Download `Open-Local-Server-1.1.0-setup.exe` from release assets, run on
Windows 10 / 11 64-bit, follow the installer. Verify the checksum against
`Open-Local-Server-1.1.0-SHA256SUMS.txt`.

Upgrading in place keeps your projects, sites, databases and settings.
