# OLS (Open Local Server) v2.0.1

**Release date:** 2026-10-01 · **Platform:** Windows 10/11 (64-bit) · **License:** GPL-3.0-only

Patch release. No new commands, settings or data models. Everything in [`v2.0.0.md`](./v2.0.0.md) works the same way —
this release is the bundle import of 2.0.0 made trustworthy on a real site, after that feature shipped and was run.

## Fixed

- **Importing a bundle no longer creates a second site.** Importing a site under the name it already has rewrote the
  project slug inside its own hostname, found the string unchanged, and fell through to the branch meant for a
  hostname that carries no project name at all — so `worpress-test` arrived as `worpress-test` *and*
  `worpress-test.worpress-test`. A hostname is now left alone when the project keeps its name.
- **A database that is already there is moved aside, not merged into.** Loading a dump over a live database
  produces something that is neither the bundle nor the old site, because a dump says nothing about the tables it
  does not mention. The old one is now kept as `<name>_bkp` (`_bkp-2`, `_bkp-3` if those are taken) and the dump
  lands in a clean database. The rename is reported in the site's own report, so the old data is still there to
  look at. The move is a catalog update on PostgreSQL; on MariaDB — which has no `RENAME DATABASE` at all, those
  are MySQL's — it is a dump, a load and a drop.
- **A WordPress site's database is found at all.** WordPress keeps its credentials in `wp-config.php` and has no
  `.env`, so a bundle of a WordPress project carried its configuration and none of its data, and importing it
  produced an empty database. The database name and engine are now read from `wp-config.php` (`DB_NAME`, and
  `DB_HOST`'s port to tell PostgreSQL from MariaDB), after the manifest and before the `.env` keys.
- **Databases OLS created itself can now be moved.** The WordPress catalog names a database after the project
  slug, so a project called `blog-dev` gets a database called `blog-dev` — a name the app's own SQL guard refused.
  Hyphens and dots are accepted now; quote characters, backslashes and spaces are still refused, and both engines
  are still quoted properly.
- **Import and export progress moves.** Both were counted in sites, which meant the bar sat still through the
  part that takes the time — copying files, loading a database — and then jumped to the end. An export counts
  sites while it gathers and zip entries while it writes; an import counts the files, `.env` files and dumps the
  manifest already declares, and reports bytes as it extracts, since the zip knows every size before the first
  byte is copied. Progress restarts cleanly when the kind of work changes.
- **Database cards stop overflowing.** On the Databases page a squeezed row wrapped `● Running on port 3306` out
  of its pill and pushed the connection URI past the edge of the card.
- **An external DB explorer is recognised for any engine** it was registered for, not only the ones that ship
  with the app.

## Changed

- **Background tasks have their own page.** They were a tab on Processes, below the system monitor and the tab
  strip, so starting an import and being sent to watch it put the list below the fold. Processes is now services
  and processes only.
- A site can say what a backup of it should copy (period, keep count, and which of settings / `.env` / databases /
  files), and a plan that would back up nothing is refused instead of silently doing nothing.
- A panicking worker no longer leaves its task marked running, and a sealed bundle entry that came back empty can
  be read rather than failing.

## Upgrading

`OLS-2.0.1-setup.exe`, verify against `OLS-2.0.1-SHA256SUMS.txt`. In place from 2.0.0: no settings, sites or
databases are migrated or changed on upgrade, and the first bundle import against a WordPress site will create the
`<name>_bkp` copy described above.
