# OpenLocalServer v1.0.0 — First Public Release

**Version:** 1.0.0
**Release date:** 2026-09-27
**Platform:** Windows 10 / 11 (64-bit)
**License:** GPL-3.0-only

## 🚀 Initial Release

This is the first public release of OpenLocalServer.

OpenLocalServer is a modern local development environment manager for Windows — runtimes, sites, databases, and trusted HTTPS, without manual system edits. Successor to XAMPP / Laragon with broader runtime coverage and full extensibility. Every project gets isolated runtimes, its own `.test` domain, and trusted local HTTPS.

One core engine (`ols-core`) powers three front doors: desktop GUI, CLI (`ols`), and local HTTP API. This release delivers the complete Windows workflow: register project → environment setup → trusted HTTPS site → develop → share.

## ✨ Key Features

### Runtimes & Toolchain

- Side-by-side versions per runtime with version manager dialog: search, install, default badge, per-version path display.
- Managed lineup: PHP NTS 8.1–8.5 (per-version extensions, Xdebug per version, PECL), Node 22/24 (corepack npm/pnpm/yarn), Composer, Python venvs, portable Git, k6.
- Online catalogs per runtime (vendor sources, 24h cache, background refresh) with resume-safe cache and atomic extract.
- Bring your own: scan folder for existing PHP installs, or register single executable (PHP/Node/Python).
- Resolution order: project manifest pin > auto-detected > global default. Changing default never touches project files.

### Sites, Web Servers & HTTPS

- Any domain + wildcard subdomains; Laragon-style automatic `<folder>.test`; static sites; reverse proxy to any host:port.
- Trusted local HTTPS: on-device CA, 397-day leaf certificates, auto-renew under 30 days, SAN-aware reuse.
- Per-site PHP version; unpinned sites follow global default.
- Nginx 1.28 / Apache 2.4 / Caddy 2.11 with generated configs; Managed / Advanced / Manual modes; validate-before-reload with rollback; drift detection; config history with diff + restore.
- Built-in wildcard DNS for `.test` / `.localhost` / `.internal`; optional elevated helper for hosts/NRPT without repeated UAC prompts.

### Projects & Reproducible Environments

- Auto-detection: framework + version from `composer.json`, `package.json`, `manage.py`, markers; workspace scan.
- Manifests (`.openlocalserver/*.yaml`): environment, services, commands, lock file.
- 14-step setup pipeline: resolve → plan → conflict report → dry-run → apply, journaled with rollback and file lock.
- Profiles (Development / Testing / Debugging / Demo), snapshots (zip, clone, import/export), lossless `.env` editor (comments/order/CRLF preserved).
- Quick Apps: 13 built-in recipes (Laravel, Symfony, WordPress, Express, React/Vite, Vue, Next.js, Django, FastAPI, static, Reverse Proxy) — validate → plan review → run with history.
- Quick Commands + project commands: discovered Composer/npm scripts with one-click run and output ring.

### Databases & Services

- Engines: MariaDB 11.4 (per-series data folders, standard port 3306), PostgreSQL 17, MongoDB, Redis (`redis-windows` community build), Mailpit, SQLite.
- Per-engine DB + user management, connection details, backup/restore (safety copy first), SQLite `.backup` + integrity checks.
- One-click external GUIs: HeidiSQL, pgAdmin 4, NoSQLBooster, Tiny RDM (auto-detected, Redis URI copy).
- Importers: Laragon / XAMPP / WampServer databases without SQL dumps (live-dump importer, with progress: step, bytes, current database).
- Service lifecycle with TCP health, Mailpit mail capture per framework (`.env` planner with diff preview), custom services (any program + args + port + health check).

### Dashboard & Monitoring

- Overview: sites/projects counts, resource donuts (CPU/RAM/disk), traffic graph from web access log (30-bucket, hover inspector).
- Diagnostics card: findings as Problem/Cause/Fix, safe one-click auto-repair, ignore list, AI explain per finding.
- Doctor: full report + repair planner; all errors surface as `Diagnostic{problem, cause, fix}`.
- Logs page (unified severity-aware viewer: search/filter/export/clear); Processes page (raw process manager + system stats); per-site usage rollups.
- Command palette (`Ctrl+Shift+P`), global search (`Ctrl+K`).

### Sharing & Tunnels

- Providers: Cloudflare, ngrok, LocalTunnel, Tailscale.
- Exposure confirmation, optional password, public badge, one-click stop.
- Traffic inspector: forwarding proxy, redacted log (500 cap), replay, webhook tester.

### CLI, API & Automation

- CLI (`ols`): `setup [--dry-run] | doctor | repair | status | start | stop`, plus `project | runtime | service | tunnel | worker | snapshot | quick-command | search | ai`; background daemon keeps working with GUI closed.
- Local HTTP API (`127.0.0.1:7420`): same `CoreCommand` JSON, bearer token, origin reject, read-only vs operate scopes.
- Workers (queue registry, max 16, Procfile.dev import), scheduler (cron, 1-min tick, no overlap), terminal (portable-pty shells with runtime PATH-first, max 8).
- Git manager: status/stage/commit/branches/pull/push/remotes/stash/clone with credential helper.
- k6 load testing (VU cap, JSON metrics), AI assistant (LM Studio / Ollama / Hugging Face / OpenRouter / OpenAI-compatible) with scoped permissions — off by default, bring your own model (`ols ai status|on|off|test|ask|explain`).
- Plugins: declarative `plugin.yaml` via minisign-signed catalogs, re-verified each load.
- Self-updater (signed `latest.json` + SHA check), tray icon, notifications, start with Windows, leftover-server cleanup, memory limits.

## 🛠️ Technical Highlights

- Architecture: one core, many front doors. `GUI (React) / CLI (ols) / HTTP API → Core::dispatch(CoreCommand) → Inner (Arc-shared state) → Managers`.
- Stack: Rust (Tokio, serde, reqwest/rustls, rcgen, portable-pty, sysinfo), Tauri 2.11, React 19 + Vite 8 + Tailwind 4 + shadcn/ui, CodeMirror 6, xterm.js.
- Single `CoreCommand` dispatcher (~150–200 variants), single `CoreResponse`, single error shape `Diagnostic{problem,cause,fix}`.
- ProcessSupervisor owns child processes (500-line output ring, crash restart, event broadcast); tree-kill via taskkill.
- Privilege separation: main app never elevated. `ols-helper` exposes closed validated set (hosts/NRPT/service) via UAC `runas` or LocalSystem named pipe.
- Declarative config: manifests, plugin.yaml, quick-app recipes with strict schema + Minijinja rendering.
- Operation journal + rollback, config versioning with drift detection, control channel via Windows named pipe + token.
- State: SQLite app database under `data/` (`OLS_HOME` overrides all paths).

## 🔒 Security

- All runtime downloads SHA-256 verified.
- Local CA key stays on-device; trust installed once to CurrentUser Root.
- Secrets in OS keyring (via `keyring`) only — never in logs, files, or bundles; secrets redacted from tunnel inspector, logs, and AI prompts.
- Tunnels require explicit first-exposure confirmation.
- AI assistant: secrets hidden before send, prompt preview, remote provider needs per-request confirmation, proposed steps limited to allowlist and run only after approval.
- Report vulnerabilities privately via GitHub Security tab “Report a vulnerability”. Include version, reproduction steps, impact. See `SECURITY.md`.

## ⚠️ Known Limitations

Built from `docs/STATUS.md` as of 2026-09-26. No clean-VM release gate has been run yet:

- Installer (NSIS/MSI) configured but never run end-to-end; E2E tests pending.
- Many screens pass type-check/lint but not checked visually in running app; expect compile fixes for modules added 2026-09-26 (`portable-pty`, `@xterm/xterm` need `cargo build` / `npm install` to refresh lockfiles).
- Helper one-time UAC install not run for real; pipe protocol tested only.
- Database import: read/dump from real Laragon data tested; load into MariaDB not tested.
- Tunnels: provider binaries (cloudflared, ngrok) found or located by hand, not downloaded. WebSockets / streamed responses bypass traffic inspector.
- Scheduler runs only while app or `ols daemon` open; no system-level scheduled task.
- Resource limits: memory applies at next service start; no CPU limit (no simple per-program cap on Windows).
- Python: venvs managed, runtime itself not managed yet.
- Redis is community `redis-windows` build (no official Windows build).
- State is a single SQLite file (`app.db`); process trees use `taskkill /T` (orphans cleaned on next start).
- Windows-only. Linux planned for 2.0.
- LICENSE copyright holder line still needs owner name.
