# OLS (Open Local Server) v2.10.0

**Release date:** in development · **Platform:** Windows 10/11 (64-bit) · **License:** GPL-3.0-only

Feature release that adds a Docker page: run and manage containers and Compose stacks, create and edit compose files (with your own presets), connect containers to your OLS sites and services, and give any container a local site with HTTPS. You can also hide sidebar pages you don't use.

## Added
- **Docker page:** a new **Docker** item under **Sites** in the sidebar. When Docker is stopped, not installed or unreachable, the page shows one clear card (no empty lists) with **Start Docker**, **Refresh**, **Retry** and the real reason. Start Docker waits for Docker to be ready and loads your data by itself. You can still **edit compose files without Docker**; actions that need Docker say "Start Docker first".
- **Your containers in one list:** **search** by name, image, port or project, plus filters for running containers, containers linked to sites, and containers created by OLS. Compose projects are collapsible groups like Docker Desktop: open by default when something runs, with **Collapse all / Expand all**, and start, stop, restart or pause a whole group at once.
- **Control containers:** start, stop, restart, pause and resume a container. Click a port to open it in your browser. **Logs** shows a container's latest output, and **Shell** opens a terminal inside a running container.
- **Container settings:** the gear on any container opens its details (ID with copy, image, command, ports, volumes, networks, labels, health) with password-like values hidden. Change its name, restart behaviour, and memory or CPU limits without restarting it, or remove it (your data volumes are kept). **Edit its environment variables**, like in Portainer: OLS recreates the container with the new values, keeps its data, and puts the old one back if anything fails. For Compose containers it opens the compose file instead.
- **Images and Volumes tabs:** see every image (size, age, which containers use it) and volume (size, who uses it); pull an image with live progress, run it with ports and variables, remove images and unused volumes. A disk-usage bar shows how much Docker uses and how much is unused, and **Reclaim space** shows exactly what a cleanup will remove, and how much it frees, before it removes anything (unused volumes are opt-in because they hold data). Long lists have search, filters and pages.
- **Compose stacks:** a **Compose** tab lists the compose files in your projects and the stacks Docker is running. Up, Stop, Restart, Down, Pull and Build with live output; **Down** keeps your data.
- **Edit compose files:** open a compose file in the built-in editor. **Check** finds mistakes (broken YAML, two services on one port, versions not pinned, passwords written in the file) and asks Docker too. **Save** keeps a backup of the old file.
- **Compose builder:** create a compose file by picking services: MariaDB, MySQL, PostgreSQL, MongoDB, Redis, Memcached, RabbitMQ, Meilisearch, Mailpit, Adminer, phpMyAdmin, PHP + Apache, Node.js, Nginx, or any other image. OLS picks free ports, generates passwords and keeps them in the Windows credential store (never in the file), and shows the file before writing it.
- **Connect to OLS:** one switch per stack lets its containers open your OLS sites by name (like `https://shop.test`), trust OLS's HTTPS certificate, and use OLS's MariaDB, Redis or Mailpit. The dialog shows the address to use for each. Your compose file is not changed.
- **Your own presets:** save your own services (image, versions, ports, environment, volumes, command) as presets in the compose builder, or turn any image you typed into one with **Save as preset**. Mark a variable as secret and OLS generates and stores its password for every new stack.
- **A site for any container:** **Create site** gives a container a local domain with HTTPS. If the container comes back on another port, the site follows it, and turning the site off or on in Sites stops or starts its container.
- **AI assistant tools:** the OLS MCP server can now check Docker, control containers and Compose stacks, create compose files, read container logs and create sites for containers. It can also bring back a site you hid with `.ols_ignore_site`.
- **Choose what the sidebar shows:** Settings → **Sidebar** lets you hide pages you don't use. Dashboard, Projects, Sites, Web server, Databases, Services, Runtimes and Settings always stay. Hidden pages still open from search (Ctrl K).

## Changed & Improved
- Docker is optional and never slows OLS down: nothing Docker-related runs when OLS starts, and the Docker page only talks to Docker while you have it open (it checks every few seconds only while Docker is stopped, and pauses when the window is hidden).
- The Docker page opens instantly: containers, images, volumes and Compose stacks are cached and refreshed in the background, and the screen only updates when something changed. The header, tabs and table headers stay in place; only the rows scroll.
- The Docker page fits small windows: long container names, image names and file paths wrap instead of hiding the buttons.

## Coming next
- **Command line for Docker:** manage containers, images, volumes and Compose stacks with `olsc docker`.
- **Warnings for Docker sites:** Diagnostics tells you when a site's container is stopped or missing.
- **Site bundles keep Docker details:** exports keep a site's Docker link and compose file, but never its passwords.
- **Dockerize a project:** generate a Dockerfile and compose file for a project in one click.

## Upgrading
Download `OLS-v2.10.0-setup.exe` and run the installer. Your settings, sites, databases, services and certificates are kept. Docker is optional: OLS does not install it, and nothing changes if you don't use it.
