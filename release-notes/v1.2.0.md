# OLS (Open Local Server) v1.2.0

**Release date:** 2026-09-30 · **Platform:** Windows 10/11 (64-bit) · **License:** GPL-3.0-only

Feature release. Product as described in [`v1.0.0.md`](./v1.0.0.md) is unchanged.

## Added
- **WordPress admin sign-in without a password.** A project whose folder holds a WordPress install
  (`wp-config.php`, `wp-admin/index.php`, or `wp-includes` + `wp-content` — checked on disk, never
  guessed from the name) gets a **WP Admin** action in its Sites row menu. Clicking it writes one
  temporary must-use plugin into `wp-content/mu-plugins` carrying a 128-bit random token, and opens
  a link that works once, on this computer, for five minutes. WordPress itself turns the token into a
  session cookie for the administrator you pick, and the helper deletes itself on the way out. No
  password is read, asked for, shown or stored; `wp-config.php` is never opened and the site
  database is never touched.
- **"Cancel pending WP sign-in"** on the same menu, for a link that was made but never used. The
  temporary file is the whole capability, so cancelling it is deleting that file. A link left behind
  by a crash is cleaned up on the next listing, and so is one whose expiry cannot be read — a file
  the app cannot age out is a file it does not keep.
- The sign-in screen reuses the app's own theme (light and dark) instead of WordPress' pages, and
  follows the colourway the app is showing rather than the operating system's.
- `olsc repair --dry-run` prints the repair plan and changes nothing. `olsc setup` already had it;
  `repair` is the command that actually changes the machine, so a preview that still asked
  "apply?" was one stray Enter away from running it. Findings print exactly as before, then a count
  of what *would* run — safe, destructive and manual — and nothing is dispatched.
- A third mode for `scripts\upload-release.bat`: `full-force-tag` (option 3 at the prompt). It is
  `full` plus re-pointing the release tag at the newest commit on `master`, for a release whose tag
  already sits behind the work its notes describe. Only the tag moves, never branch history.

## Notes
- The WordPress sign-in link is refused unless the request comes from the loopback interface, after
  its five-minute window, or on a second use. The link URL carries the token and is never written to
  the log.
- `wp_sign_in` refuses, with the fix, when the web server is stopped or the project has no domain to
  open — a link to a site that cannot answer is not a link.
- The three new commands (`list_wp_projects`, `wp_sign_in`, `wp_sign_in_revoke`) are deliberately
  absent from the local HTTP API's allow-list and from the AI command allow-list: the local API
  should not be able to mint an administrator session for a site.

## Upgrading
`OLS-1.2.0-setup.exe`, verify against `OLS-1.2.0-SHA256SUMS.txt`. In place from 1.0.0 or 1.1.1: no
settings, sites, secrets, service or certificate move. Nothing in this release changes a stored
model; the only file written into a project folder is the temporary WordPress sign-in helper, which
removes itself.
