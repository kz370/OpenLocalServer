Data models (SQLite app.db: settings table + docs collections holding JSON blobs).

Entities:
- Project {id: sha256(path)[..16], name, path, framework, created_at, updated_at}
- Domain {id, project_id, hostname, root, kind: Php{version}|Proxy{host,port,https}|Static, https, redirect_https, wildcard, enabled, ownership: Managed|Advanced|Manual, app:{executable,args,cwd,runtime}, blocks:{headers,redirects,mappings,upstreams,includes}, generated_hashes, public_domain, tunnel_id, server: nginx|apache|caddy|null, path_prefix: string|null}
  server null = served by the default web server; a set id pins the site to that one server. Exclusive: a site is rendered on exactly one server, never mirrored. An id that is no longer a known server is kept in the file and falls back to the default with a warning, never dropped (validate_domain_server rejects one on add/update).
  path_prefix = also serve the site at localhost/<path_prefix>, in addition to its own domain. One segment, 1-40 chars, lowercase letters/digits/-/_ only; "." and ".." and any "/" or "\" are refused (validate_path_prefix). Blank stores None. Unique across sites: a second site claiming one is refused naming the holder, because both would answer on the same path and only one could win.
- Fresh install seeds Domain openlocalserver.test (Static, managed, https, root data-dir/home + welcome index.html + exact logo.svg brand bytes); always ensured on load (legacy home.test auto-renamed), hidden from Sites list, remove/rename refused. Its root is re-anchored to `<data>/home` on every load, since that folder belongs to the app and not to the install path it was first written at.
- `Domain.root` is stored relative when the folder is one of the app's own (`sites/<name>` or `data/<name>`, forward slashes) and absolute otherwise, translated only at the `DomainStore` boundary (`AppPaths::encode_root` / `decode_root`). So a site under the app's own folders travels with a renamed or relocated install, while a real project folder keeps the path its owner gave it and is never rewritten. A root stored absolute by an older build that no longer exists is re-anchored from its trailing `sites`/`data`/`home` segment when that folder exists under the current install, and left untouched otherwise so a genuinely deleted site still reports as missing. Every in-memory consumer — renderers, diagnostics, search, snapshots, the API — sees a full path.
- Runtime {id, type: php|node|python|composer|mariadb|postgres|mongo|redis|mailpit|nginx|apache|caddy|sqlite|git|k6, version, path, arch, installed_at}
- RuntimeEvent = Progress{id, version, state: Downloading|Paused|Verifying|Extracting, downloaded, total} | Installed{id, version, path} | Failed{id, version, message} | Cancelled{id, version}
  InstallState (the `state` map) additionally carries Installed|Cancelled|Failed. Cancelled is a user stop, not a failure: it produces its own terminal event and no Diagnostic, and it never reaches Failed.
- InstallControl {paused, cancelled}, one per in-flight id@version, live only while that install runs. Pause holds the transfer (partial file kept, resume continues it); cancel deletes the partial download and installs nothing.
- DatabaseInstance {id, engine, version, host, port, data_path, status}
- Database {engine, name, owner} + DbUser {name, host, password_ref}
- WebConfig {default_server: nginx|apache|caddy, servers:{server_id -> ServerPorts{http, https}}, php_workers, dns_port}
  Settings keys: web.default_server, web.servers.<id>.http_port, web.servers.<id>.https_port (legacy web.server / web.http_port / web.https_port migrate into the default server's entry on load).
  effective_ports(id) = 80/443 when id == default_server, else the stored pair; stored pairs are never rewritten just because a server becomes the default. First-time pairs: apache 8080/8443, caddy 8081/8444, nginx 8082/8445.
  resolve_server(override) = override when it is a known id, else default_server.
- WebServerConfig {id, project_id, server: nginx|apache|caddy, path, managed, hash, updated_at} + ConfigHistory {hostname, timestamp, content}
- Certificate {hostname, cert.pem, key.pem, meta.json{sans, expiry}} + CaInfo {cn: OpenLocalServer Local CA, valid 2024-2044}
- Tunnel {id, project_id, provider: cloudflare|ngrok|localtunnel|mock, target, public_url, status, created_at}
- QuickApp {id, name, source: Builtin|Local|Imported, version, definition_path, trusted, favorite} + QuickRun {id, app_id, status, logs[4000 cap]}
- QuickCommand {id, name, command:{executable,arguments}|action, working_directory, source, trusted} + CommandHistory {line, exit_code, timestamp}
- Plugin {id, name, version, permissions[], enabled, path} + CatalogSource {name, url, pubkey, last_verified}
- Profile {id, name, environment, builtin} + EnvironmentManifest {runtime, web, domain, database, services, workers, scheduler, tunnel}
- Worker {id, project_id, command, count[1..16], timeout, memory} + WorkerStatus {pid, state}
- ScheduledTask {id, project_id|global, cron|every_*, command, last_run, next_run}
- ServiceStatus {id: mailpit|mariadb|postgres|mongodb|redis|nginx|apache|caddy, state, port, pid, kind: mail|sql|document|cache|custom|web, healthy, log_source}
  Web servers are proxied entries: WebManager owns the process, ServiceManager only lists and probes them (kind web, port = that server's effective HTTP port, healthy = TCP probe). + ConnectionInfo {host, port, user, password_ref}
  `log_source` names the log source holding that service's own output: `service:<id>` for a process-backed service (its stdout/stderr buffer, empty while stopped), `web:<id>:error` for a web server. It is what the UI opens Logs on, so "View logs" shows the service that was clicked instead of the app log.
- LogSource {id, name, kind: app|web|service|process|run}. Web ids are per server (`web:nginx:error`, `web:nginx:access`); the bare `web:error`/`web:access` still read the configured default server.
- ProcessInfo {id, pid, exe, args, cwd, env, state: Starting|Running|Stopping|Stopped|Crashed|Restarting|Failed, cpu, mem, exit_code}
- Settings (key-value JSON): runtime.php.global, runtime.node.global, paths.sites_dir, quickapps.projects_dir (blank = <install>\sites; blank/whitespace falls back to sites_dir), projects.roots, projects.removed (folders removed from list; rescans skip them), domains.auto, domains.auto_skip (deleted auto sites), web.*, database.default_tool.*, diagnostics.auto_fix, startup.*, notifications.enabled, api.*, updater.*
  - `projects.removed` and `domains.auto_skip` are the two deletion skip lists, and together they are the deletion history the Settings → Excluded sites card reads. Entries are objects `{value, deleted_at}` where `deleted_at` is Unix milliseconds; lists written before that (plain strings) are still read and surface as `deleted_at: 0` ("date unknown"), so an existing skip is never lost. Same value twice keeps the newest timestamp instead of duplicating the row.
  - `DeletedItem {value, deleted_at, kind: project|domain}` is the read model: both lists merged and sorted newest-first. `kind` is derived from which list the entry came from and is not stored.
  - `startup.minimized` (bool, default true) is the sole authority on startup visibility for every launch, not just the Windows startup entry; `startup.close_to_tray` (bool, default true) governs the close button separately. The startup entry is written without `--minimized` so the two never disagree.
  - `startup.services` (list of service ids) is the only auto-start setting. Web servers are ordinary entries in it: one is applied (config rendered and validated) before it starts, so the user's sites answer. The former `startup.web` switch is read once for migration only -- a user who had it on gets the default web server appended to the list -- and is never written again.
- Secrets (OS keyring, never files): tunnel tokens, db passwords, api bearer hash, git per-host creds.
- Operation journal: Operation {id, kind, CoreCommand JSON, status: Running|Done|Interrupted, retry_hint}
- Snapshot zip: manifests + sites + cert meta + workers + schedules (+ optional .env/dumps/files; skips node_modules/vendor/.venv).

Manifest (.openlocalserver/):
- runtime.yaml {php, node, python, composer}
- web.yaml {server}
- domain.yaml {hostname, https, wildcard}
- database.yaml {engine, version, host, port, database, username}
- services.yaml {redis, mailpit}
- environment.yaml (merged) + environment.lock {resolved versions}
- commands.yaml (merged QuickCommands)

Plugin (plugin.yaml):
- {id, name, version, description, author, kind: declarative, permissions[], contributes:{runtimes[], quick_apps dir, detections[], health_checks[]}}

QuickApp recipe YAML:
- {id, name, description, category, requirements{}, variables[]{id,label,type,required,default,validation,options,show_if,runtime}, steps[]{if, run/cwd/allow_failure | action + with}, files[], env_vars[], post_create[], install[], domain{}, environment{}}
- Variable types: text, number, boolean, select, multiselect, path, directory, file, password, secret, port, domain, runtime-version, database-version.

Schemas/interfaces (TypeScript core.ts mirrors Rust):
- CoreCommand (tagged union, ~200 variants), CoreResponse, Diagnostic{problem,cause,fix}, DashboardData, DomainSummary, HealthItem, WebStatus, CertInfo, ServiceStatus, ProjectDetail.
- ResourceLimits (settings key `resources`, all fields optional/null = the program's own default): mariadb_buffer_pool_mb, postgres_shared_buffers_mb, redis_maxmemory_mb, memcached_max_memory_mb, mongodb_cache_mb, cpu_percent, cpu_threads, cpu_limiter_path, node_max_old_space_mb, max_worker_count, max_processes, k6_max_vus.
  cpu_percent is 1-100 and is a share of *all* logical cores, matching `cpulimit`'s own meaning. cpu_threads is 1..=available_parallelism and is converted to that percentage, rounded up. Exactly one of the two may be set — validate refuses both — because two statements of the same limit is a setting the app would have to guess between.   cpu_limiter_path overrides the search for cpulimit.exe when the app has no copy beside it: the running exe's directory is checked first (where the installer puts it), then this field, then OLS_CPULIMIT_PATH, then the repo's vendor/cpulimit/cpulimit.exe (a compile-time path, so it only ever exists inside a checkout — what a dev build from target\ resolves), then %LOCALAPPDATA%\Programs\cpulimit, then PATH. A non-file value is skipped rather than ending the search. The binary itself is vendored at vendor/cpulimit/cpulimit.exe with a pinned SHA-256 checked on every build.
  CpuCapStatus {wanted, limiter_path, logical_cores, effective_percent, hint} rides on the `resources` response: the UI states a wanted cap and the tool that applies it separately, so it never claims a limit that is not in force.
- SettingsService and CustomInstallStore derive Clone. A read that must do slow work clones the store and releases its lock rather than holding it across that work, so lock scope is part of the model's contract, not just of the call site.
