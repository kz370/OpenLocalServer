# OpenLocalServer — Full Documentation

## 1. Introduction
OpenLocalServer is a Windows-local development environment manager. It downloads and runs PHP, Node, databases, caches, mail, and web servers, gives each project isolated runtimes plus own `.test` domain with trusted local HTTPS, without manual system edits. Pre-release, stage 15/20. Portable `data/` beside exe; `OLS_HOME` overrides paths.

Scope: runtimes (PHP/Node/Python/Composer), databases (MariaDB/Postgres/Mongo/Redis/SQLite), web (Nginx/Apache/Caddy), projects (detect/setup/env/git/workers/scheduler/snapshots), domains + TLS + DNS, tunnels, diagnostics/doctor, plugins, quick-apps/commands, AI assist, local API, CLI, updater.

## 2. Architecture
One core, many front doors. `ols-core` holds all logic behind `Core::dispatch(CoreCommand)`. Tauri shell exposes single IPC `run_command`; CLI talks over named-pipe control channel (auto-spawns daemon); HTTP API posts same JSON to `127.0.0.1:7420/v1/command`.

See `architecture_overview.md` and diagrams:
- `diagrams/architecture.mmd` — system context
- `diagrams/dataflow.mmd` — setup-to-healthy flow
- `diagrams/classes.mmd` — core classes
- `diagrams/sequence.mmd` — domain + apply sequence

State: `Arc<Inner>` shared across threads; lock order domains-first. ProcessSupervisor owns Tokio runtime + all children. Managers communicate via broadcast events (`process-event`, `terminal-event`, `runtime-event`).

Privilege model: main app never elevated. `ols-helper` closed set (hosts-apply/remove, nrpt-add/remove, install-service) via UAC or LocalSystem pipe service with SDDL lock.

Helper pipe calls are bounded: a request waits at most 10s for the service's reply, then falls back to running the change un-elevated/elevated. A wedged or killed `ols-helper` must never block the caller indefinitely — `apply_web` waits on the helper, and an unbounded wait there froze the web state lock and with it every command in the app.

## 3. Modules
### 3.1 System core
Dispatch, state, IPC, infra. `lib.rs` re-exports; `app.rs` Inner + all command impls; `command.rs` ~150-variant dispatcher; `control.rs` named-pipe RPC with token; `api.rs` localhost HTTP with bearer + allowlists; `paths.rs` resolution; `settings.rs` atomic JSON; `secrets.rs` keyring; `process.rs` supervisor; `port.rs` conflict reporter; `exec.rs` capture helper; `error.rs` Diagnostic shape; `logging.rs` + `redact.rs`; `diagnostics.rs` findings engine; `repair.rs` doctor; `search.rs` global search; `support.rs` bundle; `network.rs` probe; `journal.rs` op log; `resources.rs` caps; `elevate.rs` helper runner (pipe reply bounded to 10s).

### 3.2 Runtime
`catalog.rs` pinned HTTPS+SHA256 manifests; `catalogs.rs` minisign-signed remotes; `runtime.rs` download-verify-extract + probe; `php.rs` per-version php-cgi pools + extensions; `nodepm.rs` lockfile/corepack; `composer.rs` reader; `venv.rs` finder; `custom_install.rs` pinned paths win; `resolver.rs` manifest>detected>global; `detection.rs` marker scan; `plugin.rs` declarative plugins (wasm refused); `updater.rs` signed self-update.

### 3.3 Services
`service.rs` DB/cache/mail lifecycle + TCP probe; `custom_service.rs` user procs (custom- prefix, no shell); `dbtools.rs` external GUI detect; `mail.rs` per-framework Mailpit planner with diff; `monitor.rs` sysinfo rollup + site cost; `workers.rs` up to 16 copies; `scheduler.rs` 1-min cron tick, no overlap. Start/stop are verified, not fire-and-forget: `start` waits for the spawn to be decided (`ProcessSupervisor::wait_for_spawn`) and returns the OS error if the process never existed, keeping the reason in `start_failures` so it survives the dead process record; `stop` waits for exit and says so when a kill was ignored.

### 3.4 Web
`web/mod.rs` trait + SiteSpec; `web/manager.rs` render-validate-backup-apply-reload-health + rollback + drift; `web/nginx.rs`, `web/apache.rs` (foreground httpd, no service), `web/caddy.rs` (auto-HTTPS off, local CA); `domain.rs` validation; `ca.rs` deterministic root 2024-2044 via rcgen; `certs.rs` per-domain reuse unless SAN/<30d; `hosts.rs` idempotent block; `dns.rs` UDP wildcard; `health.rs` 5-step chain; `tunnel.rs` provider abstraction + confirm gate + port blocklist; `inspector.rs` forwarding proxy, 500 req, redacted.

### 3.5 Data
`dbbackup.rs` mysqldump/pg_dump with safety copy; `sqlite.rs` WAL-safe .backup + integrity_check; `migrate.rs` Laragon/XAMPP/Wamp live-dump importer.

### 3.6 Project
`project.rs` registry ID=sha256[..16]; `project_tools.rs` wrappers; `manifest.rs` strict YAML; `profiles.rs` templates; `setup.rs` 14-step pipeline + lock file; `snapshots.rs` zip + clone; `envfile.rs` lossless editor; `command_catalog.rs` Symfony/artisan/npm discovery; `git.rs` real binary + ASK_PASS + ~/.ssh key detection (list_ssh_keys); `shortcuts.rs`; `editors.rs`; `terminal.rs` pty max 8; `shell_menu.rs` HKCU; `procfile.rs`; `loadtest.rs` k6 VU cap 200; `xdebug.rs` trigger-default; `quickapp/*` schema->plan->run.

### 3.7 CLI / Helper / Shell / UI
CLI `ols` never manages directly; daemon mode runs core headless + scheduler clock. Helper validates ip=127.0.0.1/::1 and suffix leading-dot. Tauri shell builds tray from domains/services, single-instance, close-to-tray. Status icon: the official mark is the green 3D server-stack tile (`src-tauri/icons/*`, generated from `src-tauri/icons/source/icon-green.png`); the red twin (`src-tauri/icons/red/`) is painted on the tray icon, the main window (taskbar) and the in-app sidebar mark whenever no service and no supervised process is running, and forced while the app is shutting down. The decision lives in `status_mark` (lock-only checks, no port probes) and is applied by `sync_status_icon` after every IPC command, from the tray menu, on every process event, after autostart, and on a 2s clock so `ols stop` over the control channel, the scheduler and crashes are covered too. `status_mark` asks `ServiceManager::any_running` and then `ProcessSupervisor::is_alive` per snapshot record — the same rule `any_running` and `prune_finished` use, because a hand-written `Running | Starting` filter disagreed with `is_alive` on `Restarting` and so could call a process both alive and dead in the same tick. `Mutex<Option<bool>>` makes it repaint only on a real change, but the state is cached *after* the repaint is confirmed rather than before: a mark that raced the tray's own creation (the process-event subscriber is registered before `build_tray`) is retried by the next 2s tick instead of being frozen for the session, and every `set_icon` error is logged rather than dropped. It is emitted to the UI as `ols:status-icon` (ui `useServerStopped`) on every repaint *and* on every `show_main_window` reveal, because that channel is push-only and a webview mounting after the last state change would otherwise never learn the mark. `ui/public/favicon-stopped.svg` is the in-app red twin of `favicon.svg`. UI `core.ts` sole IPC wrapper; no router, page state + `ols:navigate` events; `Sidebar` provides persistent navigation with static non-collapsible category groups; `useWeb` shared poll 4s; pages per concern (see catalog.txt).

## 4. File Analysis
### Rust core essentials
- `lib.rs`: Purpose: crate root + re-exports. Key exports Core/CoreCommand/CoreResponse. Depends on command/paths/process/project/runtime/service/settings.
- `app.rs`: Purpose: shared Inner state + command impls. Holds supervisor/runtimes/services/certs/php/web/terminals/journal/workers/tunnels/api/ai. Lock order domains-first.
- `command.rs`: Purpose: single dispatcher. ~150 variants covering processes/runtimes/projects/services/web/DB/quickapps/AI/tunnels. Input CoreCommand JSON, output CoreResponse or Diagnostic.
- `control.rs`: Purpose: named-pipe RPC. control.json {pipe,token,pid}. Token-gated JSON lines. Handles shutdown handover.
- `api.rs`: Purpose: localhost HTTP. Port 7420, bearer SHA256, Origin reject, read_only vs operate lists, 1MB cap.
- `paths.rs`: Purpose: OLS_HOME > debug repo/data > exe data > OS app-data. migrate_legacy once.
- `process.rs`: Purpose: supervise all children. Tree-kill taskkill /T /F, 500-line ring, restart policy, broadcast.
- `runtime.rs`: Purpose: verified installs only. Zip root-strip, PATH probe 60s cache, temp version probe, broadcast Installed/Failed. One `InstallControl` per in-flight `id@version` carries the pause/cancel flags the Runtimes page drives; `install_one` returns `InstallOutcome::{Done,Failed,Cancelled}` so a user stop is never reported as an error, and the control is dropped with the install so a late pause cannot address a finished one. `refresh_online_catalog{id}` reads each vendor's public release feed (nodejs.org, downloads.php.net, nginx.org, apachelounge, getcomposer, downloads.mongodb.org, enterprisedb, api.github.com for redis-windows/memcached-windows/axllent-mailpit, downloads.mariadb.org) and keeps the result in memory only; ids with no feed (`git`, `k6`, `caddy`, `sqlite`, `python`) are refused by name. The Runtimes page gates on the same id set in `ui/src/pages/Runtimes.tsx` (`ONLINE_CATALOGS`) and re-verifies on dialog open, since its localStorage cache outlives the daemon's in-memory list. Mailpit builds its archive URL from the `v<version>` tag and carries no SHA-256 (the publisher ships none), so the download digest is recorded rather than compared, like nginx. PostgreSQL's EDB feed is the one HTML page among them: it is parsed per `Binaries from installer` block, taking the version that follows the `Version` label (React puts a `<span>` and a `<!-- -->` comment between them, so the two are never adjacent) and the href of the `alt="Windows x86-64"` anchor in that block, never the first `getfile.jsp`, which is often Mac OS X. Absolute `sbp.enterprisedb.com` hrefs are used as given, and a version with no Windows anchor is not offered. The href is a redirect, so `resolve_online_manifest` resolves the final `get.enterprisedb.com` URL over a ranged GET; the page carries no checksum, so the download digest is recorded, and the built-in 17.6 pin keeps its self-pinned hash. A transfer that ends early is rejected rather than cached: the byte count is compared against the advertised Content-Length and a short file is deleted, because for a vendor that publishes no checksum (postgres, nginx, apache, mailpit, redis, memcached) the cache-hit test trusts *any* existing file — a truncated archive would be reused forever and surface much later as `invalid Zip archive: Could not find EOCD`, naming neither the cause nor the fix. For the same reason a cached zip is only reused when its end-of-central-directory record is present (`zip_has_eocd`); a non-archive runtime such as composer.phar has no EOCD and is trusted as-is. MariaDB's rest-api is keyed by **branch**, not by full version — `mariadb_branch` cuts `13.1.1` to `13.1`, because `/rest-api/mariadb/13.1.1/` answers 200 with a `release_data` document that has no `releases` map, which made every 13.x install fail as unavailable; the branch's published SHA-256 is still required before the archive is accepted.
- `php.rs`: Purpose: FastCGI pools. One pool/version, auto curl/mbstring/pdo/openssl/opcache, zend for opcache/xdebug.
- `service.rs`: Purpose: DB/mail lifecycle. Reuses runtime + supervisor, TCP probe, no dep-ordered start yet. `is_running`/`any_running` first prune entries whose supervisor process is gone, so a service that exits or crashes on its own never stays "running" (§122).
- `web/manager.rs`: Purpose: safe apply pipeline. Archive replaced, rollback on validator fail, drift flag, manages pools/hosts/DNS.
- `domain.rs`: Purpose: domain data + sanitize. Proxy host/port checks, upstream_url, ownership gates.
- `ca.rs`/`certs.rs`: Purpose: local PKI. Deterministic CA rebuildable, 397-day leaves, reuse unless SAN/expiry, revoke=delete dir.
- `setup.rs`: Purpose: reproducible env. Order runtimes->pm->DB->domain->DNS->SSL->mail->workers->scheduler->tunnel. Journal-wrapped, rollback safe reverses, writes lock.
- `quickapp/schema.rs`/`plan.rs`/`run.rs`: Purpose: recipe safety. Strict types + regex + show_if; Minijinja strict; masked secrets in review; 4000-line log, 30-min step timeout.
- Remaining files follow same pattern: pure purpose, explicit errors, no silent fallback. Full per-file table in analysis agents; one-line index in `catalog.txt`.

### Tauri / CLI / Helper
- `src-tauri/src/lib.rs`: Tauri shell, tray, shutdown 30s wait, auto-fix loop 300s, quick-app finish poll 2s, and `reveal_window_on_ui_ready` — the main window is configured `visible: false` (the app window is transparent, so a window shown before the webview paints is an empty see-through frame); the UI emits `ols:ui-ready` after two animation frames and the window is shown then, with a 5s fallback timer and a `MAIN_WINDOW_REVEALED` guard so the app is never left running with no window. A launch that starts hidden skips both paths, leaves the window in the tray, and notifies after 2s that it is running there — the tray icon can sit in the Windows overflow area, and a launch with no window and no word reads as a failed start. `status_mark` / `apply_status_icon` / `sync_status_icon` own the green/red mark (see §3.7); `show_main_window` is the resync point for it, since a window opened from the tray has no `ols:ui-ready` to resync against, and a `stop` that fails is now surfaced instead of being dropped — a service that stayed up is exactly why the mark would stay green.
- `crates/ols-core/src/app.rs` `should_start_hidden` + `migrate_startup_entry`: The `startup.minimized` preference alone decides startup visibility, on every launch, so the toggle in Settings does what it says when the user opens the app themselves and not only at login. `--minimized` is retained as a force flag for scripts and hand-made shortcuts. The startup entry no longer carries the flag — an old entry that still did would hide the window against the user's later choice, so it is rewritten once at startup.
- `src-tauri/src/main.rs`: windows_subsystem hide console in release.
- `ols-cli/src/main.rs`: clap CLI, Ctx::call over pipe, daemon spawn detached on NotRunning, table/diag printers.
- `ols-helper/src/main.rs`: validated hosts/NRPT only; exit 5 on AccessDenied triggers UAC retry.
- `ols-helper/src/service.rs`: LocalSystem pipe, SDDL SY+BA full / IU RW, 64K line JSON.

### Frontend
- `core.ts`: only IPC caller. `App.tsx`: page state router. `main.tsx`: ThemeProvider mount, then emits `ols:ui-ready` after two `requestAnimationFrame`s so the native window is only shown once React has presented its first frame. `index.html`: a blocking inline script applies the stored theme (or the system one) to `<html class="dark">` before the first paint — the ThemeProvider effect runs after the first frame, so without it a dark-theme start flashes white on the way to dark.
- A window that has not painted is never shown: the native window is transparent, so revealing it before the first frame is what produces a blank/see-through window on launch. The UI signals `ols:ui-ready` after two animation frames and the shell reveals the window then, with a timed fallback so a UI failure cannot leave the app with no window at all.
- Pages: Dashboard (3s poll get_dashboard; a failed poll shows its Diagnostic in an ErrorCard rather than leaving the Web server / Services cards on "Loading…" forever; Services widget row = a 6-track grid (logo 1.5rem, name 1fr, port 2.5rem, state pill 5.75rem, controls 4.5rem, 3-dot menu 2rem) so those columns line up across all 9 rows regardless of name length or the web rows' extra reload button, over all 9 built-ins in fixed order; the card lives in the right half of a 2-column grid under the Web server card and stretches to the same height as Overview, so a row keeps every field (a row needs ~380px and cannot share a third of the grid) and only the name shrinks (min-w-0 + truncate); below lg that wrapper is `display: contents` and the three cards carry order 1/2/3 — Web server, Overview, Services — so a windowed app leads with server state instead of the load graphs; its row controls are colour-coded per action (start emerald, stop destructive, restart amber, reload sky, logs violet) at reduced opacity, and an action unavailable right now renders flat grey with no hover response), Sites (merge domains+orphans, group/search; creation defaults to <install>\sites via quickapps.projects_dir override, folder name/location editable per dialog), QuickApps (debounced plan 250ms, trust gate, compact responsive grid), Commands (prefix build, process-event stream), WebServer (each settings card owns its own Save and its own dirty flag — `defaultDirty` over default_server/php_workers/dns_port, `portsDirty` over the per-server http/https pairs — so an edit in one card never raises the other card's button, and each button writes only its own keys; a save writes settings and stops there, never apply_web, because php_workers is read only in apply_one and dns_port only in sync_dns so both are inert until the next start, and a save made while stopped says so beside the header buttons; every save ends in refreshConfig() so the stored config re-reads and the draft that produced it clears — refreshing without it left cfg stale, the draft permanently dirty and the button a no-op on re-click; ports tab rows are a fixed 4-column grid [minmax(0,1fr) 5.5rem 5.5rem 7rem] with 6-character-wide port inputs and an h-9 note cell, and a status badge in a row-layout CardHeader is shrink-0 + whitespace-nowrap so it cannot wrap and stretch the header), Config (ownership + DiffView), Tunnels (exposure confirm + Inspector), Databases (per-engine tools + backup-before-restore), Services (3s poll), Runtimes (runtime-event + version compare), Profiles/Plugins/Logs (1.5s poll + severity regex)/Processes (2s stats)/Settings.
- TechIcon resolves IDs to brand marks where available and generic glyphs otherwise; Memcached uses the symbol-only form of its supplied logo, while Redis keeps its own brand mark.
- Libs: hooks (usePoll/useAction), theme, web (shared state; refreshConfig re-reads the stored config, the one refresh that does, so a settings save can clear the draft it came from — the plain refresh deliberately keeps cfg to stop the 4s poll stomping an in-progress edit), ai/confirm/nav buses, wait (poll-until-real), utils cn.
- The Services widget runs its start/stop/restart through the *page's* `useAction`, so a failure reaches the ErrorCard the page already renders. A widget-local action stored its error in state nothing read, which made a failed start look exactly like a status that had silently reverted.
- A form seeded from a fetched object re-seeds only when that object's *contents* change, never on identity: `DomainSettings` keys its reset on `domain` alone (the `projects` prop changes identity on every project-folder watcher event, and re-seeding on it discarded the unsaved choice and wrote the stale value back on Save), a typed project name is not overwritten by a later `projects-changed` event, and `SiteDialog` fetches `get_domain` once per trigger and drops a read whose contents are unchanged — it used to fetch twice per open, producing two resets before anything could be typed.
- Components: SiteDialog (big tabbed editor), ProjectImports (Git clone modal with auto-detected ~/.ssh keys dropdown, refresh button, fallback browse, and import env), Terminal (xterm bridge), EnvEditor (lossless), CodeEditor (CodeMirror + diff), Diagnostics/Doctor, Release/SettingsExtras, CustomServices, PHP/Xdebug dialogs, Migrate, SystemMonitor, ui primitives (no IPC), including NumberInput: every number field in the app (web ports, PHP workers, DNS port, Xdebug IDE port, API port, custom-service port, resource limits) is a text input with inputMode="numeric" and the app's own up/down stepper — the native `type="number"` arrows are a browser widget that ignores the app's radius, border and dark palette and only paints on hover in Chromium. The field holds its own text while focused (a half-typed number is not rewritten under the cursor), but a step from the arrow keys or the chevron buttons rewrites the text too, so the displayed number always equals the value the app holds.

Runtime installs that antivirus quarantines mid-flight (the community memcached Windows port is a reliable heuristic hit) report what went wrong, why — unsigned community build — the verified SHA-256, and the Defender exclusion steps to fix it, rather than a bare OS file-not-found.

## 5. Business Rules
- Resolution manifest > detected > global; global never overrides explicit.
- Downloads require HTTPS + SHA256; mismatch aborts; catalogs minisign-verified each load.
- A runtime download in flight is the user's to control: `pause_runtime{id,version,paused}` holds the transfer where it is (the socket is not drained, the partial file is kept, and resuming continues the same transfer) and `cancel_runtime{id,version}` stops it — the partial download is deleted, nothing is extracted or installed, and the outcome is a `Cancelled` event, not a failure. Verification and extraction are not pausable, so a stop lands at the next stage boundary and the runtime is never renamed into place after one. Addressing an install that is not running is refused by name.
- Web ownership Managed/Advanced/Manual; drift preserved + flagged; invalid keeps old.
- Domains any name, default `<project>.<tld>` where tld comes from `domains.default_tld` setting (default: `local`; presets local|test|localhost or custom); wildcard via local DNS+NRPT; conflict detect; reverse proxy to any host/port; static index.php still runs PHP.
- New sites/clones/imports/QuickApps default to `<install>\sites` (writable) else user Sites; `quickapps.projects_dir` override wins, blank falls back; absolute path required, parent auto-created, non-empty target refused; per-dialog folder name/location editable; Git clone supports SSH auth with dropdown auto-detecting keys from %USERPROFILE%\.ssh, dynamic refresh button, and file-picker browse fallback.
- Local CA trusted once to CurrentUser Root; wildcard certs; HTTP->HTTPS toggle; health 5-step chain.
- DB version isolation; safety backup before restore; secrets in keyring only; redaction everywhere.
- Mailpit mandatory; .env diff preview; local mail never leaves machine.
- Tunnels default off, first start needs confirm_exposure, public badge, DB/mail/xdebug ports blocked.
- Imported quick-apps/plugins untrusted until approved; elevated steps separate confirm.
- Diagnostics {problem,cause,fix}; safe auto-fix once/session; destructive asks.
- A service action reports what actually happened: `start_service` waits for the spawn to be decided and fails with the OS reason if the process never started, `stop_service` waits for exit and fails if a kill was ignored, and `restart_service` fails on either half rather than reporting a bounce that did not happen. A process that never spawned has no output buffer to read, so the reason is kept per service and `read_log{source:"service:<id>"}` returns it instead of an empty list. Every widget on a page runs its action through that page's `useAction`, so the error reaches an ErrorCard instead of state nobody renders.
- Workers/schedulers run while app/daemon open; memory caps next restart; k6 VU cap 200.
- Snapshots zip skips node_modules/vendor/.venv; import renames domains/DBs/ports/certs.
- A control that cannot act right now must look inert, not merely dimmed: unavailable service-row actions render flat grey (`text-muted-foreground/45`, `disabled:opacity-100`, no hover tint) while enabled ones carry their action colour, so the two never read as the same button.
- In-window layout rules: a form row is a fixed-column grid, never proportional, so two rows' fields share columns; a port field is sized for the value it holds (5 digits plus the stepper) instead of stretching; a badge sitting beside a title in a row-layout CardHeader is `shrink-0 whitespace-nowrap` and the title block beside it is `min-w-0`, so neither wraps or stretches the other.
- A number field uses the app's own stepper, never a browser widget: value is `number | null` (null = empty, the field may hold nothing), min/max clamp both typing and stepping, ArrowUp/ArrowDown step while focused, the buttons are `type="button" tabIndex={-1}` and prevent mousedown so the field keeps focus and the tab order stays one stop per field, and each carries an accessible name ("Increase <field>" / "Decrease <field>") rather than a bare chevron.
- The window appears only when there is something to show: it is created hidden and revealed once the UI has painted, because the app window is transparent and an unpainted one reads as a blank flash. The stored theme is applied before the first paint, so a start never flashes the wrong theme either.
- Whether the window appears at all is the user's decision, on every launch, not only at login: `startup.minimized` alone decides. The Windows startup entry is written without a `--minimized` flag so it cannot contradict the preference, and an entry left over from an older build still carrying that flag is rewritten once at startup. A launch that starts hidden says so with a desktop notification, because the tray icon may be in the Windows overflow area and a start with no window and no word reads as a failed launch.
- The status mark must be able to say it changed. Three rules follow from that. One definition of "alive": the mark uses `ServiceManager::any_running` and `ProcessSupervisor::is_alive` rather than a second, hand-written state filter, so no process can be counted alive by one check and dead by another in the same tick. Paint before remembering: the cached value is written only after a repaint is confirmed, so a mark that lost a race with the tray's own creation is retried rather than frozen for the session, and a repaint that errors is logged rather than swallowed. Push, never fetch: `ols:status-icon` has no current-value query, so it is emitted on every reveal as well as every repaint, and a webview that mounts later is not left showing a mark the app already left behind. A mark is only claimed once it is known — a missing core reads as "running", not "red".
- Updates signed manifest + installer SHA; only own-folder exes startable; no telemetry default.

## 7. Flows
- Register -> detect -> resolve -> plan -> apply (journal) -> domain -> cert -> render -> validate -> backup -> reload -> DNS/hosts/NRPT -> services/workers/scheduler -> health. See `diagrams/dataflow.mmd`.
- Tunnel: create (untrusted token via env) -> confirm_exposure -> start supervised proc -> inspector proxy -> public badge.
- QuickApp: schema validate -> answers -> plan (review + masked secrets) -> approve source -> run background (cancel flag) -> notify.
- Doctor: diagnose -> explain -> propose CoreCommands -> confirm destructive -> re-diagnose.
- CLI offline: call -> NotRunning -> spawn daemon detached -> 30s pipe wait -> send.
