Functions / Classes / Modules / Components catalog (one-line each).

--- RUST ols-core ---
Core | Central dispatcher facade over Inner.
CoreCommand | Enum (~150 variants) covering all UI/CLI/API operations.
CoreResponse | Tagged response enum for every command.
CoreError/Diagnostic | User-facing error shape {problem,cause,fix}.
Inner | Arc-shared state holding all managers. State locks are taken through `app::lock`, which recovers a poisoned guard instead of unwrapping it — a `std::sync::Mutex` stays poisoned for the process after any panic while held, so unwrapping turned one failure into every later read panicking too. `project_detail` clones SettingsService/CustomInstallStore (both `Clone`) and drops the guards before `build_detail` does file I/O and version probes, so an unreachable project folder cannot stall other commands.
AppPaths | OLS_HOME-aware path resolver (certs/data/settings).
SettingsService | SQLite key-value store (app.db settings table). Cloneable so a read can release the store lock before doing slow work.
Db | Central SQLite store (app.db, WAL): settings table + generic docs collections for all Vec-stores.
Secrets | OS keyring wrapper (set/get/delete).
ProcessSupervisor | Owns child processes, tree-kill, output ring, restart policy. wait_for_spawn/wait_for_exit let a caller block until a spawn is decided or a process is gone; a spawn error is kept on the record and pushed into the output ring, so a process that never started still has a readable reason.
ProcessSpec/ProcessInfo/ProcessEvent | Process spawn descriptor, status, broadcast event.
PortChecker | Bind-probe + netstat/tasklist conflict reporter.
ExecCapture | Sync run-and-capture with timeout + CREATE_NO_WINDOW.
Logger | JSON daily rolling log with redaction.
Redactor | Regex secret scrubber (PEM/Bearer/URL creds/keys/cookies).
DiagnosticsEngine | Read-only findings with runnable fix_commands.
RepairPlanner | Doctor report + safe auto-repair planner.
GlobalSearch | Cross-entity prefix/word/substring search.
SupportBundle | Redacted zip exporter (summary/doctor/logs).
NetworkProbe | Parallel TCP 443 online check with cache.
Journal | Crash-safe operation log with retry/undo hints.
ResourceLimits | Optional memory caps applied next start.
ElevateRunner | Privileged ols-helper invoker with UAC fallback.
Catalog | Built-in runtime pins (URL+SHA256, HTTPS enforced).
CatalogSources | Signed remote catalogs (minisign, re-verified each load).
RuntimeManager | Download-verify-extract + version probe + events + per-vendor online version feeds (node, php, nginx, apache, composer, mongodb, postgres, redis, memcached, mailpit, mariadb). Per-install pause/cancel controls; a stop is a Cancelled outcome, not a failure.
PhpPools | Per-version php-cgi FastCGI pools + extension management.
NodePm | Lockfile/packageManager detector + corepack switch.
ComposerReader | composer.json/lock merger, vendor/scripts reporter.
VenvTools | Python venv finder + create-args builder.
CustomInstallStore | User-pinned exe paths winning over detection. Cloneable for the same reason as SettingsService.
Resolver | Version precedence manifest>detected>global.
Detector | Marker-file framework detection + workspace scan.
PluginManager | Declarative plugin.yaml installer/validator.
Updater | Minisign-signed self-updater (latest.json + SHA check).
ServiceManager | DB/cache/mail lifecycle + TCP health; also lists/proxies the three web servers (kind web) without owning their processes. start() waits for the spawn to be decided and returns the OS error if the process never started, keeping that reason in start_failures (survives the dead process record) for read_log; stop() waits for exit and errors when a kill was ignored.
CustomServiceStore | User programs as supervised services (custom- prefix).
DbTools | External GUI tools detect + launch (HeidiSQL/pgAdmin/NoSQLBooster/Tiny RDM).
MailPlanner | Per-framework .env Mailpit planner with diff preview.
Monitor | sysinfo CPU/mem/disk + per-PID rollup + site cost.
WorkerStore/WorkerProcesses | Queue workers registry + PID map.
ScheduleStore/TaskRuns | Cron tasks + 1-min ticker, no overlap.
WebServer trait | render_main/render_site/validate/start/reload/stop.
WebManager | Per-server render-write-validate-reload pipeline with rollback + drift detect; one Running entry per server, each startable on its own.
WebConfig | {default_server, servers:{id -> ServerPorts{http,https}}, php_workers, dns_port}; effective_ports(id) is 80/443 for the default and the stored pair otherwise.
ServerPorts | {http, https} - the stored pair one server keeps even while it is the default.
Server first-time ports | apache 8080/8443, caddy 8081/8444, nginx 8082/8445; two servers may never share a bound port (WebConfig::port_conflicts).
Nginx/Apache/Caddy | Server renderers + invocation builders.
DomainStore | Domain data + validation (no rendering).
LocalCa | Deterministic root CA (2024-2044) + leaf issuance.
CertificateManager | Per-domain cert lifecycle (reuse unless SAN change/<30d).
HostsBlock | Idempotent BEGIN/END block transform.
DnsServer | UDP wildcard A->127.0.0.1 for suffix list.
HealthChecker | DNS->TCP->TLS->Cert->HTTP chain.
TunnelManager | Provider abstraction (cf/ngrok/lt) + confirm gate.
Inspector | Forwarding proxy + redacted traffic log (500 cap).
DbBackup | mysqldump/pg_dump backup/restore with safety copy.
SqliteStore | WAL-safe sqlite3 .backup + integrity_check registry.
Migrator | Laragon/XAMPP/Wamp scanner + live-dump importer.
ProjectStore | Folder registry, ID=SHA256(path)[..16].
ProjectTools | Composer/npm/venv/xdebug thin wrappers.
Manifest | .openlocalserver/*.yaml strict schema.
ProfileStore | Reusable env templates (laravel/node-api/python-api/full).
SetupPlanner | 14-step resolve-plan-apply with rollback + lock file.
SnapshotManager | Zip snapshots (manifests+sites+certs meta) + clone/import.
EnvFile | Lossless .env line editor preserving comments/order/CRLF.
CommandCatalog | Symfony/artisan/npm script discovery + signature parser.
GitTools | Real-binary git via PATH/portable + ASK_PASS creds + ~/.ssh key detection (list_ssh_keys).
Shortcuts | Jump-to places + open-with guard.
EditorRegistry | VSCode/Cursor/Zed/etc detect + resolve.
TerminalManager | portable-pty shells with runtime PATH-first (max 8).
ShellMenu | HKCU Directory\shell right-click installer.
ProcfileImporter | Procfile.dev>Procfile web/worker splitter.
LoadTestRunner | k6 scripts runner with VU cap + JSON metrics.
XdebugConfig | Per-PHP ini block + IDE validator.
QuickApp Schema/Plan/Catalog/Run/Commands | Recipe validate->plan(review)->run(execute) + history.

--- CLI / HELPER / TAURI ---
OlsCli | clap CLI sending CoreCommand over control pipe, auto-spawns daemon.
DaemonRunner | Background core + scheduler clock + graceful stop.
HelperMain | Elevated closed command set (hosts/nrpt/service).
HelperService | LocalSystem resident pipe server (SDDL locked).
TauriApp | Window+tray+single IPC run_command + event emits.
TauriApp status icon | Green mark (icons/*) while any service runs, red mark (icons/red/*) on tray+window when none run and while shutting down; embedded with include_bytes!, repainted on state change only. `status_mark` decides using ServiceManager::any_running plus supervisor `is_alive` per record — the same rule `any_running`/`prune_finished` use, so a process in `Restarting` is not counted by one check and dropped by the other. `apply_status_icon` paints first and caches second, and only caches after `set_icon` actually succeeded, so a mark that raced the tray's own creation is retried by the next 2s tick instead of freezing for the session. Every `set_icon` error is logged rather than dropped. `ols:status-icon` is emitted on every repaint and on every `show_main_window` reveal, so a webview that mounts after the last state change is not left showing the wrong mark.
TauriApp window reveal | Main window configured visible:false (the window is transparent, so showing it before the webview paints is a blank see-through frame). `reveal_window_on_ui_ready` shows it on the UI's `ols:ui-ready` event (emitted from main.tsx after two rAFs) with a 5s fallback timer and a MAIN_WINDOW_REVEALED guard. `show_main_window` is also the resync point for the status mark, since a window opened from the tray never gets an `ols:ui-ready`.
app::should_start_hidden | Startup visibility decision (app.rs). The `startup.minimized` preference is the whole answer and applies to every launch — manual, startup entry, or shortcut — so the toggle means what it says. `--minimized` only forces a hidden start when the preference is off. Pure function, covered by startup_visibility_tests.
app::migrate_startup_entry | Rewrites an existing `HKCU\...\Run` value that still carries the old `--minimized`, which would hide the window even with the preference off. Missing entry is left alone; failure is logged, never fatal.
ui/index.html | Blocking inline pre-paint theme script (stored `ols-theme`, else `prefers-color-scheme`) so a dark-theme start never flashes white.

--- FRONTEND pages ---
DashboardPage | Overview with health filter + stop-all. Web server + Services cards render from one `get_dashboard` poll; a failed poll surfaces its Diagnostic instead of leaving them on "Loading…". Services widget lists all 9 built-ins in fixed order (mailpit, mariadb, postgres, mongodb, redis, memcached, nginx, apache, caddy) and collapses the port column and state pill to a titled dot below the sm breakpoint so the service name never squeezes out in a narrow window. Row controls (start/stop/restart/reload/logs) are colour-coded per action — start emerald, stop destructive red, restart amber, reload sky, logs violet — held at reduced opacity so the strip stays readable; an action the row cannot take right now (not installed, already in that state, no log source, another command running) renders flat grey with `disabled:opacity-100` and no hover response, so "unavailable" never looks like a live control. Card order flips by width: the two-column layout puts Overview in the left column and Web server stacked over Services in the right one, while the windowed/single-column layout leads with the Web server card, then Overview, then Services (`contents lg:flex` on the right-hand wrapper plus `order-1/2/3 lg:order-none`), so the narrow window answers "is the web server up?" before the load graphs. The Services widget takes the page's `run`, not a local useAction, so a failed start/stop/restart reaches the page ErrorCard.
SitesPage | Domains+projects merged table, group/search/duplicate. New Git clone / import / QuickApp defaults to <install>\sites (quickapps.projects_dir override); each dialog shows resolved path, folder name + location editable; Git clone supports SSH auth with ~/.ssh key detection dropdown, refresh button, and file-picker fallback. One removal action per row: a row with a domain offers "Delete site" (which also takes its project off the list when that was the project's last site), a row without one offers "Remove from list". The confirm dialog names the site or project in its title and the destructive button repeats the action. The row leaves the list immediately and dims with a spinner while `applying` reports the web-server update.
QuickAppsPage/Wizard | Recipe CRUD + compact responsive recipe grid (4-col xl, 3-col lg, compact cards) + 3-phase plan/run wizard.
CommandsPage | Discovered+custom commands runner with output ring.

WebServerPage | Server/ports/certs tabs. Each settings card owns its own Save and its own dirty state — `defaultDirty` (default_server, php_workers, dns_port) and `portsDirty` (per-server http/https pairs) — so an edit in one card never raises the other card's button, and each button writes only its own keys. --- FRONTEND components/lib ---
CoreClient (core.ts) | Single invoke('run_command') wrapper + all types. `runCommandWithin(command, ms)` is the same call under a deadline, rejecting with a Diagnostic that names the command; used by every read whose result gates rendered content, because a command that never answers is otherwise indistinguishable from a slow one and leaves the page on its loading state for good.
UseWeb | Shared web state hook (4s poll). Owns optimistic removal: `deleteSite`/`removeProjectFromList` drop the row at once, track it in `removing`, run the apply behind it under `applying`, and re-read the store on failure so a failed command puts the row back and a failed apply never leaves a deleted row on screen. Every fire-and-forget read here (projects refresh, runtime catalog, unmanaged PHP versions, the `projects-changed` handler) ends in an explicit `.catch`: they only decorate other pages, so a failure is dropped, but dropped on purpose.
AiBus/AiHost/AiButton | Global AI dialog bus + runner + gate.
ConfirmBus/ConfirmHost | Global confirm modal bus.
WaitHelpers | Poll-until-real (service/web/process).
NavBus | Cross-page openProject event bus.
ThemeProvider | system/light/dark with localStorage.
CommandPalette | Ctrl+K fuzzy global_search palette.
Sidebar | Persistent navigation drawer with static category groups, active item highlight, theme switcher, and public tunnel badge.
SiteDialog | Tabbed project editor (env/terminal/git/workers/snapshots/...). get_domain is fetched once per trigger and an unchanged read is dropped, so a tab bounce cannot re-seed the settings form under the user. Both gating reads (`get_domain`, `get_project_detail`) are 20s-deadline-bounded through `runCommandWithin` and report their Diagnostic in an ErrorCard with a Retry, so "Reading the site/project…" is a state that always ends. The project id comes from the `get_domain` answer (`siteProjectId`) rather than racing the id the caller arrived with, which used to fire two detail reads and leave the loser's spinner standing.
DomainDialog/DomainSettings | Add-site modal (Source project name text input auto-fills domain/folder; Address/Serves/Options) sharing FormSection + form-size Dialog with QuickApps Wizard; footer via Dialog prop, submitRef. The form re-seeds on a change to the domain's contents only, never on the `projects` prop's identity (a watcher event) or a typed project name, so an unsaved server pin is not discarded and then saved back as the stale value.
TerminalComp | xterm.js bridge to TerminalManager (lineHeight 1.3 + windowsMode so WebView2 Consolas descenders never clip; explicit light-on-black theme + visible cursor + "[starting shell…]" hint so slow startup never looks dead).
EnvEditor | .env table editor with diff.
CodeEditor/DiffView | CodeMirror yaml/nginx/apache + diff restore; content color pinned to theme foreground; Config load failure shows message, never silent blank. Requires tauri CSP style-src 'self' 'unsafe-inline' (CodeMirror injects all CSS via runtime <style> tags; blocked CSP = unstyled scaffold).
DiagnosticsCard/DoctorDialog | Findings list + doctor runner.
ReleaseCards | API/shell-menu cards. Updates card is just a releases-page link (in-app updater UI removed).
SettingsExtras | Resource limits + settings backup cards.
CustomServices | Custom service CRUD table.
PhpExtensionsDialog/XdebugDialog | PHP extension toggles + xdebug form.
MigrateDialog | Foreign DB scan + import progress.
SystemMonitor | CPU/mem/disk + process rollup display.
Ui primitives | button/card/dialog/input/form/table/menu/switch/badge/checkbox (Tailwind/Radix, no IPC). Dialog sizes default/form(max-w-2xl shared form-modal)/wide; FormSection shared headers; Field errors with icon, hint swap no-shift. NumberInput (input.tsx) | number field with an app-styled stepper: text input + inputMode="numeric" + role="spinbutton" + two ChevronUp/ChevronDown buttons (size-3.5, rounded-[4px], text-muted-foreground/80, hover:bg-muted, active:bg-accent, disabled:opacity-30, tabIndex -1, onMouseDown preventDefault so the caret is kept). Native type="number" is not used anywhere: its arrows are a browser widget that ignores the app radius/palette and only paints on hover in Chromium. min/max clamp both typing and stepping; value is `number | null` (null = empty); ArrowUp/ArrowDown step by 1 while focused; the raw text is held locally while the field is focused so a half-typed number is not rewritten under the cursor, but a step (arrow key or chevron) also rewrites the text from the new value, so the box always shows the number the app holds; a step starts from the number on screen (not the value prop) and is clamped+truncated before display.
