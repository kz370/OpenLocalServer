Each test takes about 2 minutes. Most need one real project, so set that up first.

## Before you start
1. Create a small Laravel project with a database: Quick App → Laravel works.
2. Make sure it opens in the browser at its `.test` address.
3. Turn on Git in the project folder (`git init`, then make one commit).

---

## 1. Migration guard
1. Turn it on in **Settings → Databases**, if it isn't already on.
2. Add a few rows to any table.
3. Run a migration from OLS, not from the built-in terminal (terminal commands aren't covered).
4. Delete the rows you added.
5. Click **Rewind** in the popup, or in the project's **Backups** tab.

**You should see:** the rows you deleted come back.

## 2. Free up space
1. Run `npm install` in an old project so it has a `node_modules` folder.
2. Go to **Projects → Free up space**.
3. Tick that folder and delete it.

**You should see:** the folder is gone and disk space goes up. Run `npm install` again and the project still works.

## 3. PHP upgrade check
1. Open the site's settings, where you pick its PHP version.
2. Pick a newer PHP and start the check.

**You should see:** a list of what would break, or a clear "safe" result. Switch with one click, then switch back.

## 4. Import from Laragon, XAMPP or WampServer
Only works if one of them is installed.
1. Open **Import sites and databases**.
2. Pick a few sites and import them.

**You should see:** the sites open in OLS with HTTPS. The old tool still works the same as before.

## 5. Faster installs (Defender)
1. Go to **Settings → General**.
2. Read the warning, then add the exclusion.
3. Time `npm install` before and after.

**You should see:** a faster install. This step changes a Windows security setting, so remove the exclusion afterwards if you only want to test.

## 6. Profiler
1. Install Xdebug for the site's PHP version.
2. Open the project's **Profiler** tab and profile a page.

**You should see:** the slowest functions and a call chart.

## 7. Dump viewer
1. Turn it on in **Settings**.
2. Click start in the project's **Dumps** tab.
3. Add `dump('hello');` to a route and open that page.

**You should see:** "hello" appears in OLS, not on the page. Clicking the file and line opens your code.

## 8. Database per Git branch
1. Turn it on in the project's **Git** tab.
2. Run `git checkout -b test-branch`.
3. Add a row to a table.
4. Run `git checkout main`.

**You should see:** the new row isn't on `main`. `.env` points at the other database.

## 9. Pull a server database
You need a server you can reach over SSH.
1. Go to the project's **Backups** tab, then the pull-from-server section.
2. Save an SSH profile and pull the database.

**You should see:** the data arrives with fake emails and names, and the downloaded file is deleted.

## 10. Security checks
1. Open the project's **Security** tab and run the check.
2. Open **Diagnostics**.

**You should see:** the Security tab lists any packages with known holes. Diagnostics warns about any PHP, Node, Python or database version that no longer gets security fixes. Installing an old Node like 18 makes sure there's something to warn about.

## 11. Open a site on your phone
1. Connect the phone to the same Wi-Fi as the PC.
2. Open the site's **Domains** panel and turn on phone access.
3. Scan the QR code with the phone.
4. Follow the guided steps to install the certificate.

**You should see:** the site opens on the phone with a lock icon and no warning.

## 12. Sleeping services
1. Go to **Services → Sleep when unused** and turn it on for MariaDB.
2. Close every app that's connected to MariaDB and wait.
3. Open a page of your site.

**You should see:** MariaDB stops on its own. When you load the page, it starts again and the page works.

---

If a step doesn't match what's on screen, note which test and step it was. That's probably a bug.
