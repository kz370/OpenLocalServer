- **Nothing new runs at app startup** except where a task explicitly allows it (Task 12's tick, and only when the user turned it on).
- No new `setInterval` polling in the UI. Use the existing patterns: refresh on page open, the Tauri events listed below, or the `ols-scheduler` minute tick (`crates/ols-core/src/scheduler.rs`, `start_clock`).

### 0.3 Traps that already cost time (avoid them)
| Trap | What to do |
|---|---|
| **Mixed line endings.** The repo is LF, but `ui/src/core/commands.ts`, `responses.ts`, `types/*.ts` and `specs/full_documentation.md` (and a few others) use CRLF. A careless Python read/write converts the whole file and makes a huge diff. | Prefer the Edit tool. For scripts, use the helper in §0.5 (`newline=''`). Afterwards `git diff --stat <file>` must show only your lines. |
| `ui/src/core/commands.ts` has a couple of LF-only lines inside a CRLF file. | Do not normalize them. `git diff` must show no `-` lines you did not mean. |
| **Prettier** is not used here; running it reformats whole files. | Hand-format to match the neighbors. `npm run lint` is the check. |
| `cargo fmt --all` reflows code you just wrote, so a later search-and-replace on the old text matches nothing. | Run `cargo fmt --all` **before** any scripted edit, and assert each old string is found. |
| A failing script followed by `;` lets a half-finished commit happen. | Chain with `&&`, or start scripts with `set -e`. |
| A dialog drawn behind other cards (blur layers). | Render `<Dialog>` **outside** any `<Card>` (see `ui/src/components/docker/DiskUsageBar.tsx`). |
| `NumberInput` rounds to whole numbers. | Fine for minutes/days in this plan. For fractions use a `Select`. |
| Port `8080` is reserved for Apache, and ports must be unique per site. | In tests use high ports (`18080`+), or better, bind port `0` and read the assigned port. |
| Some tests always fail on Linux CI containers (Windows registry, keyring, shell). | Compare failures against `main` (§0.4), not against zero. |
| A heredoc Python script on Windows Git Bash gets CRLF-mangled. | Put scripts in a file in your scratchpad and run `python -I <file>` (see the memory note "Python CRLF gotcha"). |
| Fixed-width tables in the UI wrap in narrow windows. | Use container queries (`@container`, `@2xl:` …) like `ui/src/pages/Sites.tsx` does. Test a narrow window. |

### 0.5 CRLF-safe edit helper (Python, for scripted doc edits)
```python
def edit(p, old, new):               # replace once; fail loudly if not found
    s = open(p, newline='').read(); crlf = s.count('\r\n') > s.count('\n')//2
    if crlf: old = old.replace('\n','\r\n'); new = new.replace('\n','\r\n')
    assert old in s, (p, old[:60]); open(p,'w',newline='').write(s.replace(old,new,1))
def app(p, text):                    # append a line at the end
    s = open(p, newline='').read(); nl = '\r\n' if s.count('\r\n') > s.count('\n')//2 else '\n'
    open(p,'w',newline='').write(s.rstrip('\r\n') + nl + text.replace('\n', nl))
```

## Task 1 (§168): Migration guard

**Goal:** before OLS runs a command that changes a database's structure (`php artisan migrate`, `manage.py migrate`, `prisma migrate`, …), it saves a copy of the project's database. One click on **Rewind** puts it back.

**User story:** "I ran `migrate:fresh` on the wrong project. I click Rewind and my data is back."

### Design (decided, do not redesign)
- **Where it hooks:** `Inner::spawn_project_process` in `crates/ols-core/src/app/quickapp/commands.rs`. Every Quick Command, every command line typed into OLS (`RunCommandLine`) and every project tool command goes through it. Terminal sessions (`terminal.rs`, a real PTY) are **not** covered, and the UI says so.
- **Detection:** a pure function `pub fn migration_kind(program: &str, args: &[String], project_root: &Path) -> Option<&'static str>` in the new `crates/ols-core/src/migration_guard.rs`.
  - Normalize `program`: take the file name, lowercase it, and strip `.exe`, `.cmd`, `.bat`.
  - Compare args case-sensitively, except `program`.
  - **Match exactly these rules** (return the label in quotes):

| program | args start with | label |
|---|---|---|
| `php` | `artisan`, then one of `migrate`, `migrate:fresh`, `migrate:refresh`, `migrate:reset`, `migrate:rollback`, `db:wipe`, `db:seed` | `"laravel"` |
| `php` | `bin/console` or `bin\console`, then one of `doctrine:migrations:migrate`, `doctrine:schema:update`, `doctrine:database:drop`, `doctrine:fixtures:load` | `"symfony"` |
| `python`, `python3`, `py` | `manage.py`, then one of `migrate`, `flush`, `loaddata`, `reset_db` | `"django"` |
| `npx`, `pnpm`, `bunx`, `yarn` (optionally `exec`/`dlx` as args[0]) | `prisma`, then `migrate` + (`dev`/`reset`/`deploy`), or `db` + `push` | `"prisma"` |
| `npx`, `pnpm`, `yarn` | `sequelize` or `sequelize-cli`, then `db:migrate`, `db:migrate:undo`, `db:migrate:undo:all`, `db:seed:all` | `"sequelize"` |
| `alembic` | `upgrade` / `downgrade` | `"alembic"` |
| `wp`, or `php` + `wp-cli.phar` | `db` + (`reset` / `import`) | `"wp-cli"` |
| `npm`, `pnpm`, `yarn` | `run <script>` (or `yarn <script>`) where `package.json` `scripts[<script>]`, run through `migration_in_line`, matches one of the rows above | `"script"` |

  - **Never match** `migrate:status`, `migrate:install`, `--pretend`, `showmigrations`, `prisma migrate status`. Only the listed verbs match.
  - `migration_in_line(line: &str)` splits with the existing `plan::split_command_line` and calls `migration_kind` again. **Recursion depth is 1**: no further script lookups.
- **Which database:** extract the database-discovery block from `Inner::snapshot_content` (`crates/ols-core/src/snapshots.rs`, from the comment "A site's database is whatever its configuration points at" through `databases.push(...)`) into `pub(crate) fn project_database(&self, project_id: &str) -> Option<crate::snapshots::DatabaseMeta>` on `Inner`, in `snapshots.rs`, and call it from `snapshot_content`. This is a **behavior-preserving refactor**: the existing snapshot tests must pass unchanged. Tasks 9 and 10 reuse it. SQLite: use the same `.env` logic (`DB_CONNECTION=sqlite`, `DB_DATABASE`=path, relative to the project root; Laravel's default when empty is `database/database.sqlite`).
- **The copy:**
  - MariaDB / PostgreSQL: `crate::dbbackup::dump_to(&i.services, engine, db, &part)`, then rename `.sql.part` to `.sql` (same pattern as `dbbackup::backup`).
  - SQLite: `std::fs::copy` of the database file (plus `-wal` / `-shm` if present).
  - Storage: `paths.backups_dir()/guard/<engine>/<database>.<unix-secs>.sql` (or `.sqlite`), plus a sidecar `<same name>.json` holding `GuardSnapshot`.
  - **Keep the newest 10 per (engine, database)**; delete older ones right after a new copy succeeds. Only guard copies are ever deleted, never the normal `backups/<engine>/` files.
- **When the copy cannot be made** (service not running, dump fails): **do not start the command**. Return `CoreError::failed_fix("OLS did not run this migration.", "<why>", "Start <engine> on the Services page and run it again, or turn off Migration guard in Settings → Databases.")`. The command would almost always fail anyway without a running database.
- **Size limit:** before dumping, ask the size (MariaDB: `SELECT COALESCE(SUM(data_length+index_length),0) FROM information_schema.tables WHERE table_schema='<db>'`; PostgreSQL: `SELECT pg_database_size('<db>')`, through `run_sql_query`). If it is above `db.migration_guard.max_mb` (default `1024`), **skip the copy and start the command**, and add a notice (see UI). If the size query fails, dump anyway.
- **Settings:** `db.migration_guard` (bool, **default `true`**; this is a safety feature, so it is on by default and is the one exception to rule 0.1.9: it never changes data and only adds a few seconds before a migration), `db.migration_guard.max_mb` (u64, default 1024), `db.migration_guard.keep` (u32, default 10, range 1–50).
- **Data model:**
```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct GuardSnapshot {
    pub id: String,            // file name without extension, e.g. "shop.1762600000"
    pub project_id: String,
    pub engine: String,        // "mariadb" | "postgres" | "sqlite"
    pub database: String,      // db name, or the sqlite path relative to the project
    pub file: String,          // absolute path of the copy
    pub created: u64,          // unix secs
    pub size: u64,
    pub command: String,       // the command line, run through crate::redact first
    pub kind: String,          // label from migration_kind
}
```
- **Commands** (dispatch in `command/dispatch/database.rs`):
  - `ListGuardSnapshots { project_id: Option<String> }` → new `R::GuardSnapshots { snapshots: Vec<GuardSnapshot> }`, newest first. Read-only, so it is automatically on the API.
  - `RewindGuardSnapshot { id: String }` → background task kind `"guard-rewind"`, target = id. It uses `dbbackup::restore` (which **first takes a safety backup** of the current state). For SQLite: copy the current file to `<file>.before-rewind-<secs>` first, then copy the guard file over it. Returns `R::TaskStarted`.
  - `DeleteGuardSnapshot { id: String }` → `R::Ok`.
  - **Validate `id`** with `snapshots::is_plain_file_name` and look it up in the list. Never build a path from user text.
- **Response for the run command does not change.** The UI learns about a copy by calling `list_guard_snapshots` after starting a command (see UI).
- **MCP:** add read-only `ols_list_migration_snapshots` (optional `project_id`). Rewind stays UI/CLI only.
- **CLI:** new group `olsc db` (`Db(DbCmd)` in `args.rs`, handler `crates/ols-cli/src/commands/db.rs`, +1 source file): `olsc db guard list [<project>]`, `olsc db guard rewind <id>` (waits for the task and prints the result; copy how `olsc docker compose` waits for tasks).

**Goal:** one place that says "these projects use packages with known vulnerabilities" and "this PHP/Node/database version no longer gets security fixes".

### Design (decided)
**Part A: end-of-life (offline, cheap)**
- New data file `crates/ols-core/catalog/eol.json`, **built at development time, never fetched at runtime**:


## Task 3 (§170): Free up space

**Goal:** find `node_modules`, `vendor`, build caches and similar folders in projects you have not touched for a while, show their sizes, and delete the ones you pick. These folders can always be rebuilt with `npm install` / `composer install`.

### Design (decided)
- `crates/ols-core/src/reclaim.rs`.
- **Scan scope:** only **registered projects** (`inner.projects`). Never a whole drive, never the project roots themselves.
- **Candidates: a closed list.** A folder is a candidate only if its path relative to the project root is one of these, **and** the condition holds:

| relative path | condition (all must hold) | rebuild with |
|---|---|---|
| `node_modules` | `package.json` exists in the same folder | `npm install` / `pnpm install` / `yarn` (pick from the lockfile) |
| `packages/*/node_modules`, `apps/*/node_modules` (one level only) | that folder has `package.json` | same |
| `vendor` | `composer.json` exists **and** `vendor/autoload.php` exists **and** `vendor` is not tracked by Git (if `.git` exists: `git ls-files --error-unmatch vendor/autoload.php` fails; without Git: `composer.lock` exists) | `composer install` |
| `.next`, `.nuxt`, `.svelte-kit`, `.turbo`, `.parcel-cache`, `.angular/cache` | `package.json` exists | the next build/dev run |
| `target` | `Cargo.toml` exists in the project root | `cargo build` |
| `.venv`, `venv` | `requirements.txt` or `pyproject.toml` or `Pipfile` exists | Repair → recreate venv. **Not selected by default.** The UI warns: "The site stops working until the environment is recreated." |

- **Never follow links.** Walk with `std::fs::symlink_metadata`. On Windows, treat any entry with `FILE_ATTRIBUTE_REPARSE_POINT` (0x400, via `std::os::windows::fs::MetadataExt::file_attributes()`) as size 0 and never enter it. pnpm uses junctions inside `node_modules`; we must never count or delete files outside the project through them.
- **Size:** sum file sizes, with a 15 s time limit and 2 million entries per candidate. When a limit is hit, report `size_is_minimum: true` ("at least 4.1 GB").
- **Last used:** the newest mtime among the project root's direct children, **excluding** the candidate folders and `.git`, plus the mtime of `.git/HEAD` / `.git/index` if present. `idle_days = (now - newest) / 86400`.
- **Busy projects are skipped:** a project is `busy` when the supervisor has a running process whose `cwd` is inside the project (`inner.supervisor` list; check the field names in `crates/ols-core/src/process.rs`), or a worker for it is running. Busy rows are shown but cannot be selected ("Stop its processes first").
- **Commands** (dispatch in `command/dispatch/tools.rs`):
  - `ScanReclaim` → background task kind `"reclaim-scan"`; the report is kept in a new `Inner` field `reclaim: Mutex<Option<ReclaimReport>>` (add it in `app/mod.rs` `Inner::new`/`with_parts` the same way other `Mutex` fields are created).
  - `GetReclaimReport` → `R::ReclaimReport { report: Option<ReclaimReport> }`.
  - `ReclaimFolders { items: Vec<ReclaimItem> }` with `ReclaimItem { project_id: String, relative: String }` → background task kind `"reclaim"`.
- **Delete rules: re-check everything at delete time, trust nothing from the UI:**
  1. The project exists and is not busy **now**.
  2. `relative` matches the closed list **exactly**: compare path components; `packages/<x>/node_modules` where `<x>` is one plain component (`is_plain_file_name`). No `..`, no absolute paths, no drive letters.
  3. `full = project_root.join(relative)`. `std::fs::canonicalize(full)` must start with `canonicalize(project_root)`.
  4. The condition from the table still holds.
  5. If `full` itself is a reparse point (a junction or symlink), remove **only the link** (`std::fs::remove_dir`), never its target.
  6. Otherwise `std::fs::remove_dir_all(full)`. Rust ≥ 1.58 does not follow junctions or symlinks inside; add a comment saying so and check `rustc --version` ≥ 1.58.
  7. Locked files (antivirus, a running process) → that item is reported as `partial` with the error; continue with the others.
  - Permanent delete, not the Recycle Bin: these folders are huge and rebuildable. The confirm dialog says so.
- **Data model:**
```rust
pub struct ReclaimReport { pub scanned_ms: u64, pub projects: Vec<ReclaimProject>, pub total_bytes: u64 }
pub struct ReclaimProject { pub project_id: String, pub name: String, pub path: String, pub idle_days: u64,
                            pub busy: bool, pub items: Vec<ReclaimCandidate> }
pub struct ReclaimCandidate { pub relative: String, pub kind: String /* node_modules|vendor|build-cache|rust-target|venv */,
                              pub bytes: u64, pub size_is_minimum: bool, pub rebuild: String, pub default_selected: bool }
```
- **No MCP. CLI:** `olsc project reclaim [--days 90]` (scan + print), `olsc project reclaim --delete --days 90 --yes` (deletes the default-selected items of idle projects only; without `--yes` it prints what it would do and exits with code 1).

### UI
- `ui/src/pages/Projects.tsx` toolbar: button **Free up space** (icon-only when narrow, like the other toolbar buttons) opens the new `ui/src/components/project/ReclaimDialog.tsx` (+1 file).
- Dialog: an "Unused for at least [30 / 60 / 90 / 180 days / any]" select (default 90), **Scan** (shows task progress), a list grouped by project (name, idle days, checkboxes per folder with size and "rebuild with …"), the total selected, and **Delete selected**.
- Confirm: "Delete 12 folders (8.4 GB)? They are removed permanently, not moved to the Recycle Bin. Run the rebuild command shown next to each one to get them back."
- After the task: "Freed 8.1 GB. 1 folder could not be fully removed (a file is in use)." with Details.

### Steps
1. `reclaim.rs`: candidate matcher (pure), walker, scan, delete, busy check.
2. Commands, TS, CLI, UI.
3. **Tests (required, in temp dirs):**
   - Matcher: `vendor` without `autoload.php` is not a candidate; `vendor` tracked by Git is not (init a repo in the test; skip the test if `git` is missing and say so); `..\\x` and `C:\\x` and `packages/a/b/node_modules` are rejected.
   - A **junction** (`std::os::windows::fs::symlink_dir`, or `mklink /J` through `cmd`, under `#[cfg(windows)]`) inside `node_modules` pointing outside the project: the scan does not count the outside files, and the delete leaves the outside folder and its file intact. **This test is mandatory.**
   - `node_modules` that is itself a junction: only the link is removed.
   - A busy project cannot be deleted from even if the UI sends it.
4. Docs. Release note: "**Free up space:** Projects → Free up space finds `node_modules`, `vendor` and build caches in projects you have not used for a while and deletes the ones you pick (they can be rebuilt any time)."

**Done when:** gate passes, including the junction test; a scan of a real projects folder lists sizes; deleting one `node_modules` frees the space and `npm install` restores it.
**Do NOT:** scan outside registered projects; delete anything not on the closed list; follow links; offer this through MCP.

## Task 4 (§171): PHP upgrade check

**Goal:** before switching a site from PHP 8.1 to 8.4, OLS shows what would break: Composer packages that need another PHP, missing extensions, and files that no longer compile. Then it switches with one click and can switch back.

### Design (decided: uses only tools OLS already has, no downloads)
- `crates/ols-core/src/php_upgrade.rs`.
- `CheckPhpUpgrade { hostname: String, target: String }` → background task kind `"php-upgrade-check"`, target `<hostname>@<version>`. The `target` must be an **installed** PHP version (check with the runtime manager). Otherwise fail with a fix: "Install PHP <v> on the Runtimes page first."
- The site must be a PHP site (`SiteKind::Php { version }` in `crates/ols-core/src/domain/types.rs`). `from` = its pinned version or the default it follows.
- **Checks, in order** (each produces `UpgradeItem { level: "blocker"|"warning"|"info", title, detail, file: Option<String>, line: Option<u32> }`):
  1. **Composer platform check.** If `composer.json` exists: run Composer **with the target PHP** (`php<target> composer.phar check-platform-reqs --lock --format=json --no-interaction`). Get the target php.exe and Composer path the way `project_program` does, but force the target version: `inner.project_program` takes a `values` map with `php_version`, so read `quick_resolve_program` and pass `php_version = target`. `--lock` needs Composer ≥ 2.3; if the output is not JSON, run it again without `--format=json` and parse the text lines `<name> <version> <status>`. Status `failed` → blocker ("laravel/framework v9 needs php ^8.0.2 <8.3"), `missing` → blocker for `ext-*`.
  2. **Extensions.** Collect `ext-*` names from `composer.lock` (`packages[].require` + `platform`) and `composer.json` `require`. Compare with `inner.php.extensions(target)` (in `php.rs`; enabled ones). Missing but available (shipped or in `pecl-pins.json`) → warning "Turn on <ext> for PHP <target> (Runtimes → PHP → Extensions)". Missing and not available → blocker.
  3. **Compile check (lint).** Run the target `php.exe -l -d display_errors=1 -d error_reporting=E_ALL <file>` on every `*.php` under the project, **skipping** `vendor`, `node_modules`, `storage`, `var`, `cache`, `.git`, `bootstrap/cache`, `wp-content/cache`. Limits: 20,000 files, 4 files at once (a small thread pool), 10 s per file. Parse the output:
     - `Parse error: … in <file> on line <n>` / `Fatal error: …` → blocker.
     - `Deprecated: … in <file> on line <n>` → warning (for example PHP 8.4's implicitly nullable parameters).
     - `No syntax errors detected` → nothing.
     Show the paths relative to the project.
  4. **PHPCompatibility, if the project already has it** (`vendor/bin/phpcs` and `vendor/phpcompatibility/` exist): `php<target> vendor/bin/phpcs -q --report=json --standard=PHPCompatibility --runtime-set testVersion <target>- --ignore=vendor/*,node_modules/*,storage/* .` Parse `files.*.messages[]`; `ERROR` → blocker, `WARNING` → warning. If it is not installed, add an info line: "For deeper checks, add `phpcompatibility/php-compatibility` as a dev dependency." **Never install it.**
- **Report:** `PhpUpgradeReport { hostname, from: String, to: String, checked_ms, items: Vec<UpgradeItem>, files_checked: u32, truncated: bool, can_switch: bool /* no blockers */ }`. Keep the newest one per site in memory (`Inner` field `php_upgrade: Mutex<HashMap<String, PhpUpgradeReport>>`), with `GetPhpUpgradeReport { hostname }` → `R::PhpUpgradeReport { report: Option<…> }`.
- **Switching** reuses the existing site update command that changes `SiteKind::Php { version }`. Find what `ui/src/components/site/SiteDialog.tsx` sends when the PHP version changes, and **do not add a new switch command**. The UI keeps `from` so **Switch back** sends the same command with the old version.
- **No MCP. CLI:** `olsc php check-upgrade <hostname> <version>` (waits, prints blockers/warnings, exit code 1 if blockers).

### UI
- In `SiteDialog.tsx` where the PHP version is picked: when the user picks a **higher** version, show a line "Check this site with PHP <v> first?" with **Check**. Results open in the new `ui/src/components/site/PhpUpgradeDialog.tsx` (+1 file): a summary ("2 blockers, 5 warnings, 1,240 files checked"), items grouped by level, file:line opening in the editor (the `open_in_editor_at` command from Task 8; until Task 8 exists use the existing `open_in_editor` with the file only), and buttons **Switch to <v>** (disabled with blockers, but **Switch anyway** is available behind a confirm) and, after switching, an Undo toast **Switch back to <from>**.
- The Task 2 EOL Diagnostics finding's fix text points here.

### Steps
1. Parsers (pure): composer check-platform-reqs JSON and text, lint output, phpcs JSON.
2. Task + report storage + commands + TS + CLI.
3. UI.
4. **Tests (required):** fixtures for each parser (include a Windows path `C:\sites\shop\app\Foo.php` and CRLF output); the skip list really skips `vendor` (temp dir with a broken `vendor/x.php` gives no blocker); a target version that is not installed fails with the fix text; `can_switch` is false when any blocker exists.
5. Docs. Release note: "**PHP upgrade check:** before switching a site to a newer PHP, OLS checks its Composer packages, extensions and every PHP file with the new version, then switches with one click (and back)."

**Done when:** gate passes; checking a real Laravel site against 8.4 produces a report; switching and switching back work.

## Task 5 (§172): Import sites from Laragon, XAMPP and WampServer

**Goal:** people switching to OLS bring their sites in one go. OLS already imports their **databases** (`crates/ols-core/src/migrate.rs`, `MigrateDialog.tsx`); this adds their **sites** (domains + folders).

### Design (decided)
- `crates/ols-core/src/migrate_sites.rs`. **Read-only on the old tools**: never write, rename or delete anything in their folders or configs.
- **Find installs** by reusing the root discovery in `migrate.rs` (`grep -n "fn laragon\|fn xampp\|fn wamp\|on every drive" crates/ols-core/src/migrate.rs`). If the root finder is private, make a `pub(crate) fn tool_roots() -> Vec<(tool, PathBuf)>` from the existing code (refactor only; the existing DB import tests must pass unchanged).
- **Sources:**
  - **Laragon:** `<root>/etc/apache2/sites-enabled/*.conf`, `<root>/etc/nginx/sites-enabled/*.conf`, and "auto virtual hosts": every folder `<root>/www/<name>` becomes `<name>.<tld>`. The TLD comes from `<root>/usr/laragon.ini`, key `HostnameFormat` (for example `{name}.test`); the default is `{name}.test`. Only `{name}` is substituted; any other template → skip auto hosts and add a note.
  - **XAMPP:** `<root>/apache/conf/extra/httpd-vhosts.conf`.
  - **WampServer:** `<root>/bin/apache/apache*/conf/extra/httpd-vhosts.conf` (every Apache version folder).
- **Apache parser** (pure, `parse_apache_vhosts(text) -> Vec<RawVhost>`): case-insensitive directives; `#` comments; CRLF; values in quotes or bare. Inside `<VirtualHost …>` … `</VirtualHost>` read `ServerName`, `ServerAlias` (many names), `DocumentRoot`. Ignore everything else (including `Include`, which is **not** followed). Unclosed blocks are dropped.
- **nginx parser** (`parse_nginx_servers`): brace-depth tokenizer that understands `#` comments and quotes; inside `server { … }` read `server_name` (many) and `root`. Ignore `include`.
- **Paths:** forward or back slashes, quotes removed. Expand Laragon's `${LARAGON_ROOT}` / `%LARAGON_ROOT%` style variables if present by plain string replace with `<root>`. Other `${…}` → skip that vhost with a note.
- **Filter:** drop names `localhost`, `_`, `*`, `_default_`, IPs, and anything that fails `crate::domain::store::validate_hostname`. Drop document roots that do not exist (shown as "folder missing", not importable).
- **Candidate:**
```rust
pub struct SiteImportCandidate { pub source: String /* "Laragon (C:\\laragon)" */, pub hostname: String,
    pub aliases: Vec<String>, pub document_root: String, pub project_root: String,
    pub exists: bool, pub already_in_ols: bool, pub note: Option<String> }
```
  `project_root` = the parent of the document root if the document root's last component is `public`, `web`, `public_html` or `htdocs/<x>/public`; otherwise the document root itself.

  - `ListSiteImportCandidates` → `R::SiteImportCandidates { candidates }` (read-only).
  - `ImportSites { items: Vec<SiteImportChoice { hostname: String, document_root: String, new_hostname: Option<String> }> }` → background task kind `"site-import"`. For each item: re-scan, and require that the item matches a current candidate (same hostname + document root). Then use the **existing** add-project + add-domain path the "Add site from existing folder" flow uses (find it: `grep -n "AddProject\|AddDomain\|CreateSiteForProject" crates/ols-core/src/command/types/commands.rs` and read the UI flow in `AddProjectDialog.tsx`), with HTTPS on (OLS default). Skip existing hostnames (report them). Aliases: add them if the domain model's `aliases` field accepts them (it exists: `certs::names_for` reads `domain.aliases`).
  - At the end, apply web config once (not per site).

## Task 7 (§174): Profiler (Xdebug profile viewer)

**Goal:** "Why is this page slow?" Click **Profile a request**, load the page, and see which functions took the time, inside OLS.

### Design (decided: uses the Xdebug OLS already ships)
- Xdebug profile mode exists: `XdebugSettings.modes` may contain `"profile"` (`crates/ols-core/src/xdebug.rs`), and files go to `output_dir = php.ini_dir(version).join("xdebug")` (`php.rs` `write_ini`).
- **Change to `XdebugSettings::ini_block`, only when `modes` contains `"profile"`:** also write `xdebug.profiler_output_name=cachegrind.out.%u.%H` (microsecond time + host) and `xdebug.use_compression=0` (plain text, so no gzip decoder is needed). Without `profile`, the block is byte-for-byte unchanged; **update the existing test at `xdebug.rs:172` only by adding a new test** for the profile case.
- `crates/ols-core/src/profiler.rs`:
  - `list_profiles(inner) -> Vec<ProfileFile { file: String /* name only */, php_version, host: Option<String>, created_ms, size }>` over every installed PHP version's xdebug dir, newest first. `host` is parsed from the name after the time part (Xdebug writes `%H` with `.` kept, so read it as "everything after the second dot-group"; write a test with real names like `cachegrind.out.1762600000_123456.shop.test`).
  - `parse_cachegrind(reader) -> Profile`: a **streaming** line parser of the callgrind format Xdebug 3 writes:
    - header `events: Time_(10ns) Memory_(bytes)`: use the first event as time, in 10 ns units;
    - `fl=(id) [name]`, `fn=(id) [name]` with name compression (an id seen with a name, later only the id);
    - cost lines `<line> <time> <mem>`, added to the current function's **self** cost;
    - `cfl=`, `cfn=(id)`, `calls=<count> <line>`: the **next** cost line is the inclusive cost of that call, added to the caller → callee edge and **not** to self;
    - `summary:` / `totals:` lines.
    - Ignore unknown lines. Refuse files over **300 MB** with a clear message.
  - `Profile { total_time_ns: u64, functions: Vec<FnStat { name, file, self_ns, inclusive_ns, calls }> /* top 300 by inclusive */, tree: CallNode }`. Build `CallNode { name, inclusive_ns, calls, children }` from `{main}`, following edges greedily. **Depth limit 40, at most 30 children per node, skip a function already on the current path (cycles).** Children below 0.5 % of total are merged into "other". Label it in the UI as "approximate: Xdebug records totals per function, not every path".
- **Commands** (dispatch in `command/dispatch/tools.rs`):
  - `ListProfiles` → `R::Profiles { files }` (read-only).
  - `GetProfile { file: String }` → `R::Profile { profile }`. **Validation:** `file` is a plain file name, starts with `cachegrind.out.`, and exists in one of the xdebug dirs. Parse on a blocking thread; it may take seconds.

  - `SetSiteProfiling { hostname, on: bool }`: find the site's PHP version, read its `XdebugSettings` (existing getter used by `XdebugDialog.tsx`; find the command it sends), add/remove `"profile"` in `modes` (never touch other modes; if the modes are `["off"]`, replace them with `["profile"]`, and when turning off with only `profile` left, set `["off"]`), make sure `start_with_request` is `"trigger"` (set it **only** if it is `"yes"` when turning on, and remember the old value in setting `xdebug.profiling_prev_start.<version>` to restore it when turning off), make sure the xdebug extension is enabled (if it is not, fail with a fix "Turn on Xdebug for PHP <v> on the Runtimes page"), save through the **same code path** as the existing Xdebug settings command, and restart that PHP version's pool through the existing restart path.
- **Opening a profiled request:** the UI opens `<site url>/?XDEBUG_TRIGGER=1` with `open_url`. Explain that the query string may confuse some routes, and that the Xdebug helper browser extension (or a cookie `XDEBUG_TRIGGER=1`) works for any page.

## Task 8 (§175): Dump viewer

**Goal:** `dump($user)` in a Laravel/Symfony project shows up in OLS, with the file and line clickable, instead of breaking the page layout. Like the paid "dump" tools, but free.

### How it works (decided: uses the project's own Symfony VarDumper, no custom protocol)
Symfony's VarDumper (used by Laravel and Symfony) can send dumps to a **dump server** instead of the page when `$_SERVER['VAR_DUMPER_FORMAT'] = 'server'` and `$_SERVER['VAR_DUMPER_SERVER'] = '127.0.0.1:<port>'`. Laravel's own dumper registration leaves `server` alone. The project's `vendor/bin/var-dump-server` is that server: OLS runs it as a supervised process and shows its output. **OLS never decodes PHP serialized data**, which avoids a whole class of security problems.

### Design
- `crates/ols-core/src/dumps.rs`.
- **Requirement per project:** `vendor/symfony/var-dumper/Resources/bin/var-dump-server` exists (it is the target of `vendor/bin/var-dump-server`). Otherwise the UI says: "This project needs symfony/var-dumper: `composer require --dev symfony/var-dumper` (Laravel and Symfony already have it)."
- **Global switch:** setting `php.dump_capture` (bool, default **false**). When true, `php.rs` `write_ini` adds **before** the user overrides block:
  `auto_prepend_file = "<data>/services/php/ols-prepend.php"` (forward slashes, quoted; get the dir from `paths.services_dir().join("php")`).
  - If the user's `overrides.ini` or any `conf.d/*.ini` already contains `auto_prepend_file`, **do not add ours**. Instead, `GetDumpStatus` reports `conflict: true` and the UI explains it.
  - Turning the switch on or off restarts the PHP pools once (existing restart path). Starting or stopping a project's dump server afterwards does **not** restart PHP.
- **The prepend file** is shipped as `crates/ols-core/catalog/php/ols-prepend.php` (`include_str!`) and written (only if the content differs) to `<data>/services/php/ols-prepend.php` by `write_ini` when the switch is on. Exact content:
```php
<?php
// Generated by OpenLocalServer for the dump viewer. Rewritten on every PHP start; do not edit.
// It only sets two $_SERVER values for sites whose dump viewer is running. It never outputs anything.
(static function (): void {
    if (PHP_SAPI === 'cli' || isset($_SERVER['VAR_DUMPER_FORMAT'])) {
        return;
    }
    $map = @include __DIR__ . '/ols-dumps.php';
    if (!is_array($map)) {
        return;
    }
    $host = strtolower((string) ($_SERVER['HTTP_HOST'] ?? ''));
    $host = (string) preg_replace('/:\d+$/', '', $host);
    if ($host !== '' && isset($map[$host]) && is_string($map[$host])) {
        $_SERVER['VAR_DUMPER_FORMAT'] = 'server';
        $_SERVER['VAR_DUMPER_SERVER'] = $map[$host];
    }
})();
```
- **The map file** `<data>/services/php/ols-dumps.php`, rewritten atomically (write `.tmp`, then rename) whenever a dump server starts or stops:
```php
<?php return ['shop.test' => '127.0.0.1:9913', 'www.shop.test' => '127.0.0.1:9913'];
```
  Built only from hostnames that pass `validate_hostname` (no quotes possible), lowercased, and ports as `u16`. Use the format `'%s' => '127.0.0.1:%u'`. Unit-test that a hostname with `'` can never reach the file.
  On app start, if no dump server is running, write an **empty map** `<?php return [];` (this is the only startup work: one small file write, and only when the switch is on).
- **CLI processes** (artisan tinker, queue workers, tests) do not use the prepend. `spawn_project_process` adds the env vars `VAR_DUMPER_FORMAT=server` and `VAR_DUMPER_SERVER=127.0.0.1:<port>` **only** for projects whose dump server is running. Workers started before that need a restart, and the UI says so.
- **Commands** (dispatch in `command/dispatch/tools.rs`):
  - `StartDumpServer { project_id }`: requires the switch on, no conflict, and the requirement file present. Pick a port: the first free one from 9912 up (`crate::port::port_is_free`), max 9999. Start the process through `inner.spawn_project_process("php", &["vendor/bin/var-dump-server", "--host=127.0.0.1:<port>"], None, Some(project_id), "Dumps: <name>", …)`, so the project's PHP is used. Record `project_id → (process id, port)` in an `Inner` field `dump_servers: Mutex<HashMap<String, (ProcessId, u16)>>`, then rewrite the map with **all hostnames of all domains of that project**. → `R::ProcessStarted { id }`.
  - `StopDumpServer { project_id }`: stop the process, remove it from the map, rewrite. → `R::Ok`.
  - `GetDumpStatus { project_id }` → `R::DumpStatus { enabled: bool /* switch */, conflict: bool, supported: bool /* requirement file */, running: Option<ProcessId>, port: Option<u16> }`.
  - If the process exits on its own (supervisor), the map still points to a dead port, and VarDumper then **falls back to printing on the page** (its documented behavior). That is acceptable. `GetDumpStatus` cleans up dead entries (check whether the process is still running) and rewrites the map.
  - At app exit, existing supervisor shutdown stops the processes. On next start the map is emptied (above).
- **Output:** the UI reads the process output with the existing `get_process_output { id }` (it is a 500-line ring; check `process.rs`). That is enough for 2.12: the panel says "Shows the newest 500 lines". Do not change the ring size globally.
- **Clickable file:line.** New command `OpenInEditorAt { path: String, line: u32 }` (dispatch next to `OpenInEditor` in `maintenance.rs`):
  - `path` must exist and be inside a registered project (canonicalize both and check the prefix). Otherwise refuse: this stops "open any file" abuse.
  - Add `pub fn open_args_at(exe: &Path, path: &str, line: u32) -> Vec<String>` in `editors.rs`:
    - `code`, `code-insiders`, `codium`, `cursor`, `windsurf`, `trae` (exe stem, case-insensitive) → `["-g", "<path>:<line>"]`;
    - JetBrains (`phpstorm64`, `webstorm64`, `idea64`, `pycharm64`, `rider64`, `goland64`, and the same without `64`) → `["--line", "<line>", "<path>"]`;
    - `sublime_text`, `subl`, `zed` → `["<path>:<line>"]`;
    - `notepad++` → `["-n<line>", "<path>"]`;
    - anything else → `open_args(exe, path)`.
  - Then reuse `launch_editor` with these args (refactor `launch_editor` to take the args vector; `open_in_editor` keeps passing `open_args`). **Test each editor family.**
- **No MCP. No CLI.**

### UI
- Settings → PHP area (or the Runtimes PHP section; pick where the Xdebug switch lives): switch **Dump viewer** with the one-line explanation, plus the conflict message if any.
- `projectToolTabs.ts`: add `{ id: 'dumps', label: 'Dumps' }` after `'terminal'`. New `ui/src/components/project/DumpsPanel.tsx` (+1 file):
  - Start/Stop button and status;
  - output shown with the existing output viewer used for Quick Command runs (find it: `grep -rn "get_process_output" ui/src`), refreshed the same way those runs refresh, **only while the tab is open and the server runs**;
  - lines matching `/([A-Za-z]:[\\/][^\s"'<>|]+?\.php)(?:"|'|\s)*(?:on line|:)\s*(\d+)/` become links that send `open_in_editor_at`;
  - **Clear** (just clears the view);
  - notes: "dd() and dump() now go here instead of the page. dd() still stops the request." and "Restart workers to send their dumps here too."
- **Security of the view:** output is plain text in `<pre>` (React-escaped). **Never** render it as HTML.

### Steps
1. `editors::open_args_at` + `OpenInEditorAt` + tests. 2. Prepend + map writer + `write_ini` change + tests. 3. Dump server commands + env injection. 4. TS + UI.
5. **Tests (required):**
   - `write_ini` with the switch off produces **exactly** the old ini (compare with the output before your change on a fixture).
   - With the switch on, the `auto_prepend_file` line is there and comes before the overrides block.

## Task 9 (§176): Database per Git branch

**Goal:** switching to branch `feature/login` gives the project its own copy of the database (`shop__feature_login`), so migrations on one branch never break another. Switching back to `main` uses the main database again.

**Depends on:** Task 1 step 1 (`Inner::project_database`).

### Design (decided)
- `crates/ols-core/src/branch_db.rs`.
- **Opt-in per project**, stored in setting `projects.branch_db` = `{ "<project_id>": BranchDbConfig }`:
```rust
pub struct BranchDbConfig {
    pub enabled: bool,
    pub engine: String,             // "mariadb" | "postgres" | "sqlite"
    pub base_branch: String,        // the branch active when it was turned on, e.g. "main"
    pub base_database: String,      // DB name, or sqlite path relative to the project
    pub clone_from: String,         // "base" (default) | "current"
    pub map: BTreeMap<String, String>, // branch -> database (never contains base_branch)
}
```
- **Turning on** (`SetBranchDb { project_id, enabled: true, clone_from }`) requires all of:
  - the project has `.git` **as a directory** (worktrees and submodules, where `.git` is a file, are refused: "not supported yet");
  - `.env` exists and `DB_DATABASE` is set; `project_database()` returns mariadb/postgres/sqlite;
  - `.env` is **not tracked** by Git (`git ls-files --error-unmatch .env` fails). If it is tracked, refuse: "OLS would change a file you commit.";
  - the base database exists and its service is running;
  - the current branch is not detached.
  Then save the config with `base_branch` = the current branch and `base_database` = the current `DB_DATABASE`.
- **Turning off:** set `.env` `DB_DATABASE` back to `base_database`, `enabled:false`. **Keep** `map` and the branch databases; the UI lists them for deletion.
- **Watching:** one thread `ols-branch-db`, started only when at least one project is enabled (at startup only if the setting has an enabled entry, which is cheap, plus whenever one gets turned on). It uses `notify_debouncer_mini` (as in `app/projects/manage.rs`) with a 1500 ms debounce on each enabled project's `.git` directory, **non-recursive**, filtering events whose file name is `HEAD`. The thread exits when nothing is enabled.
- **On a HEAD change** for project P:
  1. Read `.git/HEAD`. `ref: refs/heads/<name>` → branch `<name>`; anything else (detached) → do nothing.
  2. If `<name>` == the last handled branch for P, do nothing.
  3. Target database: `base_database` if `<name> == base_branch`; else `map[<name>]` if it exists; else a **new name** `branch_db_name(base_database, <name>)`.
  4. If the target does not exist: start a background task kind `"branch-db"` (target = project id; the task registry already refuses duplicates) that **creates the copy**:
     - **MariaDB:** `create_database(to)`, then `dump_to(from)` into a temp file under `paths.cache_dir()`, then `load_into(to)`, then delete the temp file. On failure `drop_database(to)`. (Same steps as `ServiceManager::rename_database` without the final drop. Add `pub fn clone_database(&self, engine, from, to) -> Result<(), String>` to `service.rs`, next to `rename_database`.)
     - **PostgreSQL:** first try `CREATE DATABASE "to" TEMPLATE "from"` (fast). It fails while `from` has connections, so on error fall back to dump/load as for MariaDB.
     - **SQLite:** `std::fs::copy` to `<dir>/<stem>__<slug>.<ext>`; the `.env` value becomes that path in the same relative/absolute form as the base.
     - `from` = `base_database` if `clone_from == "base"`, else the database currently in `.env`.
  5. When the target exists (after the copy if needed): set `.env` `DB_DATABASE` to the target with `envfile::set` (lossless; keeps comments and CRLF), store `map[<name>] = target` (unless base), and then:
     - restart the project's **workers** (`WorkerStore` entries for the project → `restart_worker`) so they reconnect;
     - if `bootstrap/cache/config.php` exists (Laravel config cache), **do not delete it**; notify: "Laravel's config cache still points to the old database. Run `php artisan config:clear`." with a button that runs that exact command through `RunCommandLine` for the project;

## Task 10 (§177): Pull a server database, with anonymizing

**Goal:** `olsc db pull shop staging --anonymize` (or a button) copies the staging/production database to your machine over SSH, and replaces emails, names, phone numbers and passwords with fake ones before you ever open it.

> **Privacy warning (UI + manual):** a server database usually holds real people's data. Pull with anonymizing whenever you can. Without it, you are copying personal data onto your laptop, and you are responsible for protecting it. OLS deletes the downloaded dump file as soon as it is imported.

**Depends on:** Task 1 step 1 (`project_database`).

### Design (decided)
- New files `crates/ols-core/src/remote_db.rs` (SSH pull) and `crates/ols-core/src/anonymize.rs` (rules + SQL).
- **Limits for 2.12:** the remote server is Linux/macOS with `sh`; SSH **key authentication only** (`BatchMode=yes`; OLS cannot answer password prompts); engines MariaDB/MySQL and PostgreSQL. Say this in the UI.
- **SSH client:** `C:\Windows\System32\OpenSSH\ssh.exe` if it exists, else `ssh.exe` on PATH, else the portable Git's `usr\bin\ssh.exe` (look at how `git.rs` finds Git). If none is found, fail with a fix: "Install the OpenSSH Client in Windows Settings → System → Optional features."
- **Remote profile**, stored in setting `projects.remote_dbs` = `{ "<project_id>": [RemoteDb] }`:
```rust
pub struct RemoteDb {
    pub id: String,          // slug of name: [a-z0-9-]{1,32}
    pub name: String,        // "staging" (shown to the user)
    pub ssh_target: String,  // "deploy@1.2.3.4" or an alias from ~/.ssh/config
    pub ssh_port: Option<u16>,
    pub engine: String,      // "mariadb" | "postgres"
    pub database: String,
    pub db_user: String,
    pub db_host: String,     // default "127.0.0.1" (as seen from the server)
    pub db_port: Option<u16>,
    pub has_password: bool,  // the password itself is in the keyring
}
```
  The password is stored in the keyring under `remote_db:<project_id>:<id>` through `crate::secrets` (look at how ngrok tokens are stored). Never in settings, logs or task output.
- **Validation (every field, every time, before any process starts).** Each is a hard error naming the field:
  - `ssh_target`: `^[A-Za-z0-9._-]+(@[A-Za-z0-9._-]+)?$`, length ≤ 255, **must not start with `-`**.
  - `database`: `is_safe_identifier` **and** no `.`/`-` at the start.
  - `db_user`: `^[A-Za-z0-9_.-]{1,64}$`.
  - `db_host`: `^[A-Za-z0-9.-]{1,253}$` or an IPv4.
  - Ports: `1..=65535`.
  - `name`: 1–40 printable characters (display only; never used in commands).
- **Remote command.** Built only from validated values; every value is put in single quotes for `sh`, which is safe because no value can contain `'`. MariaDB:
```text
sh -c 'IFS= read -r P; export MYSQL_PWD="$P"; if command -v mariadb-dump >/dev/null 2>&1; then D=mariadb-dump; else D=mysqldump; fi; exec "$D" --single-transaction --quick --routines --triggers --no-tablespaces --default-character-set=utf8mb4 -h '"'"'<db_host>'"'"' -P '"'"'<port>'"'"' -u '"'"'<user>'"'"' '"'"'<database>'"'"''
```
  Build it in Rust as: an inner script string with each value single-quoted, then wrap the whole script as `sh -c '<script with ' → '"'"'>'`. **Write one function `sh_quote(s) -> String` and use it for both layers. Unit-test that the final string, given validated values, round-trips through a POSIX shell parser.** If writing a parser test is too much, test the exact expected string for a fixed input. PostgreSQL: the same, with `export PGPASSWORD="$P"` and `exec pg_dump --no-owner --no-privileges --clean --if-exists -h … -p … -U … <database>`.
  - The password goes on the ssh process's **stdin** followed by `\n`, then stdin is closed. It is never in argv (visible in the process list) and never in a file.
  - SSH args: `["-o","BatchMode=yes","-o","ConnectTimeout=15","-o","ServerAliveInterval=30", (if port) "-p","<port>", "--", ssh_target, remote_command]`.
  - Run with `std::process::Command` (hidden window via `exec::hide_window`), stdout to `paths.cache_dir()/pull-<project_id>-<secs>.sql.part`, and stderr captured and **redacted** (`crate::redact`) for errors. Report bytes received to the task about once a second. Honor task cancel (kill the child).
  - Exit code ≠ 0 → fail with stderr's last 20 lines (redacted). Common fixes in the message: "Permission denied (publickey)" → "Add your SSH key to the server"; "command not found" → "mysqldump/pg_dump is not installed on the server".
- **Import flow** (`PullRemoteDb { project_id, remote_id, mode: "replace" | "new", anonymize: bool, confirm_real_data: bool }` → background task kind `"db-pull"`, target project id). Steps reported to the task:
  1. Preflight: profile valid, password present if `has_password`, the local engine running, `network::check(false).online`, and `anonymize || confirm_real_data` (otherwise refuse: the UI must have asked).
  2. Download (above).
  3. Create the local temp database `free_database_name(engine, "<local>__pull")` and `load_into` it.
  4. If `anonymize`: load the rules (below) and run them on the **temp** database. On any error: drop the temp database, delete the dump, fail. The local database is untouched.
  5. `mode == "replace"`: `dbbackup::backup(local)` (so it is in the backups list), `drop_database(local)`, `rename_database(temp → local)`. `mode == "new"`: `rename_database(temp → free_database_name("<local>_<remote id>"))`, and report the name. The UI then offers **Use it** (sets `.env` `DB_DATABASE` through the existing env editor command).
  6. **Always** (success, failure or cancel): delete the `.sql.part`/`.sql` file. Use a guard struct whose `Drop` deletes it. On app start, delete any leftover `cache/pull-*.sql*` (cheap: one `read_dir`; this is allowed startup work).
- **Anonymizing rules:** file `<project>/.openlocalserver/anonymize.yaml`. It holds no secrets, so the team can commit it:
```yaml
version: 1
tables:
  users:
    key: id                 # a column used to make fake values unique
    columns:
      email: email          # user_<key>@example.test
      name: name            # User <key>
      first_name: name
      last_name: empty      # ''
      phone: phone          # 000-000-0000
      password: password    # bcrypt hash of the word "password"
      remember_token: "null"
      address: "fixed:Redacted"
  password_reset_tokens: truncate
  sessions: truncate
```
  - Kinds (a closed set): `email`, `name`, `phone`, `password`, `null`, `empty`, `fixed:<text>` (≤ 100 chars), `keep`. Table values: a map (as above), or the string `truncate`.
  - Every table, column and key name must match `^[A-Za-z_][A-Za-z0-9_]{0,63}$`. Quote identifiers with backticks (MariaDB) or double quotes (PostgreSQL).
  - `fixed:` text becomes a SQL **string literal through the existing escaping helper** in `service.rs` (the "Single-quoted literal" function near line 279; check its name and that a MariaDB equivalent exists, and add one if not, escaping `\` and `'`).
  - SQL per kind, MariaDB / PostgreSQL:
    - `email` → `CONCAT('user_', \`key\`, '@example.test')` / `'user_' || "key" || '@example.test'`
    - `name` → `CONCAT('User ', \`key\`)` / `'User ' || "key"`
    - `phone` → `'000-000-0000'`
    - `password` → the constant `'$2y$10$92IXUNpkjO0rOQ5byMi.Ye4oKoEa3Ro9llC/.og/at2.uheWG/igi'` (the well-known bcrypt hash of "password" used by Laravel factories)
    - `null` → `NULL`, `empty` → `''`, `fixed:x` → literal
  - One `UPDATE <table> SET c1 = …, c2 = …` per table and `TRUNCATE TABLE <t>` for truncate (PostgreSQL: `TRUNCATE TABLE "t" CASCADE`). Run through `run_sql` against the temp database (check how `run_sql` picks the database; add a `database` parameter variant if needed, without changing existing callers).
  - A table or column missing in the database → fail before changing anything (check `information_schema.columns` first), and name the missing one.
  - `SuggestAnonymizeRules { project_id }` → reads the **local** database's columns and suggests kinds for names matching (case-insensitive) `email`, `*_email` → email; `name`, `first_name`, `last_name`, `full_name`, `username` → name; `phone`, `mobile`, `*_phone` → phone; `password` → password; `*token*`, `*secret*` → null; `address*`, `street`, `city`, `zip`, `postcode`, `ip_address`, `last_login_ip` → `fixed:Redacted`; and tables `sessions`, `password_reset_tokens`, `password_resets`, `failed_jobs`, `personal_access_tokens`, `oauth_access_tokens` → truncate. It returns YAML **text** for the user to review. `SaveAnonymizeRules { project_id, yaml }` validates the YAML and writes the file (create `.openlocalserver/` if needed).
- **Commands:** `ListRemoteDbs { project_id }`, `SaveRemoteDb { project_id, remote: RemoteDb, password: Option<String> }` (a password is stored to the keyring; `None` keeps the existing one; an empty string removes it), `DeleteRemoteDb { project_id, id }` (also removes the keyring entry), `TestRemoteDb { project_id, id }` (runs the same SSH command with `--no-data` and a 30 s timeout, as a quick task), `GetAnonymizeRules { project_id }`, `SuggestAnonymizeRules`, `SaveAnonymizeRules`, `PullRemoteDb`.
- **Not on the HTTP API, not in MCP** (data exfiltration risk). `list_remote_dbs` and `get_anonymize_rules` are read-only by name, so **explicitly exclude them from the API**: read how `api.rs` decides `reads` and add a small deny list `NEVER_API: &[&str] = &["list_remote_dbs", "get_anonymize_rules", "suggest_anonymize_rules"]` checked first. Add a test.
- **CLI:** `olsc db pull <project> <remote> [--anonymize] [--new] [--yes-real-data]`. Without `--anonymize` it requires `--yes-real-data`. `olsc db remotes <project>` lists the profiles (never the password).

### UI

  - the profiles list with **Add** / **Edit** / **Test** / **Delete**. The form validates the same patterns client-side for nicer errors; the server validates again.

## Task 11 (§178): Open a site on your phone

**Goal:** test a site on a real phone on the same Wi-Fi, **with working HTTPS**: scan a QR code, install OLS's certificate once, done.

### Design (decided)
**Part A: a LAN hostname per site**
- New `Domain` field `lan: bool` (`#[serde(default)]`), plus `lan_alias: Option<String>` (`#[serde(default, skip_serializing_if = "Option::is_none")]`) computed by OLS, not typed by the user.

## Task 12 (§179): Services sleep when unused, wake on connect

**Goal:** on a laptop, MariaDB, PostgreSQL, Redis, MongoDB and Memcached stop after N minutes without connections (saving RAM and battery) and start again by themselves when an app connects.

### Design (decided)
- `crates/ols-core/src/idle.rs`.
- **Scope:** service ids `mariadb`, `postgres`, `redis`, `mongodb`, `memcached` only. Never web servers, Mailpit, custom services or Docker.
- **Setting** `services.idle` = `{ "<service id>": { "enabled": bool, "minutes": u32 (5..=240, default 30), "wake_on_connect": bool (default true) } }`. Empty or missing = off for all (the default).
- **Port:** the service's main port. Use the same source the services list shows (`ServiceStatus` port, or `crate::service::known_port(id)` / the `primary_port` used by `sql_client`; read `service.rs` to pick the one that reflects user port changes).
- **Activity check:** in the `ols-scheduler` minute tick (`scheduler.rs` `start_clock` loop: add `crate::idle::tick(&inner);` after the auto-backup tick). `tick` returns at once if no service has `enabled: true`. Otherwise it runs `netstat -ano -p TCP` **once** (`run_capture`, 5 s timeout) and parses it with the pure `fn established_on_ports(output: &str, ports: &[u16]) -> HashMap<u16, u32>`: lines `TCP <local>:<port> <remote> ESTABLISHED <pid>`, IPv4 `a.b.c.d:p` and IPv6 `[::1]:p`; count where the **local** port matches. `netstat` output is localized on some Windows languages, but `ESTABLISHED` is not translated; still, if no line parses at all, skip this tick and log once.
- **State** (in `Inner`, field `idle: crate::idle::IdleState`): per service `last_active: Instant`, `slept: bool`, an optional listener handle.
  - Connections > 0 → `last_active = now`.
  - Running, enabled, `now - last_active >= minutes`, and `now - service start time >= minutes` (use `last_active` initialized when OLS first sees the service running) → `services.stop(id)`, `slept = true`, notification "MariaDB was stopped after 30 minutes without use. It starts again when an app connects." (or "…Start it on the Services page." without wake).
  - Pure function `should_sleep(last_active, now, minutes) -> bool`, unit-tested.
- **Wake on connect** (only if `wake_on_connect`): right after the idle stop, start a thread `ols-wake-<id>`:
  1. `TcpListener::bind(("127.0.0.1", port))`. On error (the port is taken) → log, set `slept` but no listener, and stop.
  2. Blocking `accept()`. On the first connection, keep the accepted socket(s): set the listener non-blocking and accept any more for 200 ms. Then **drop the listener** (frees the port).
  3. `services.start(id)` (through `Core::dispatch(StartService)` semantics if reachable, so the UI state machine updates; otherwise `inner.services.start(id)` then `publish_current_state`). Wait until `is_running_and_ready(id)`, up to `crate::service::service_ready_timeout(id)`.
  4. For each held client: connect to `127.0.0.1:port` and pipe both ways (two threads with `std::io::copy`, shut down the other side when one ends). If the start failed, just close the clients.
  5. `slept = false`, `last_active = now`.
  - **Known limit (in the UI and manual):** "The first connection waits a few seconds while the service starts. A second new connection in that same moment may fail once." Only `127.0.0.1` is listened on; apps that connect to the LAN IP or `::1` do not wake it.
